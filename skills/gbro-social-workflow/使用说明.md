# GBro 图文工作流使用说明

为 AiGoodBro 核验来源，按当前范围制作 X、微博、小红书、抖音、TikTok、B站、公众号、视频号稿件、教程和商品素材，完成封面内页及定版交付。普通图文默认真实分享的质感，按材料选择实操记录、界面批注或观点短卡，红蓝色、卡通全身人物或半身头像、已确认字标轻量出现，不再使用旧软件图标。具体细节和个人判断先于品牌包装；大字与精细图解可以保留，字体与层级沿用实际看过的确认样稿，不逐张重新设计，也不用假经历或故意粗糙制造自然感。小红书图文 3:4、10 个不重复话题（包含 `#AiGoodBro`）和独立桌面的机器人路线是本账号约定；bridge 中沿用当前绑定身份，当前任务要求优先。

每次发布先读已指定的来源对话和最新作品回执，复用成功入口，不重新摸索。重置消息正文第一句和新视频开场先说日期、具体时间、时区，再说 ultra + fast 等行动提示；用当次时间，不套旧日期。续接入口与失败处理见[发布续接](references/publishing-continuity.md)。

正式调用名为 `$gbro-social-workflow`，日常说“gbro”或“gbroskill”即可。旧名称 `gbaskill`、GBAskill、goodbroskill 都转到同一主入口；规则统一维护在本目录。

小红书发布用 **social-auto-upload（SAU）**，对应 Skill 为 `xiaohongshu-upload`，本机入口为 `gbro-publish xiaohongshu`。它能登录、验会话、发视频／图文和定时；上传命令默认真实提交，没有草稿开关。各工具是否会发帖、是否只填稿、哪些字段缺失以及登录和浏览器限制，统一见[工具边界](references/platform-tools.md#操作边界速查)，同步保存在已有 Obsidian 渠道笔记；不能把安装、登录或排期当作公开发布成功。

读笔记另有入口：已知小红书链接可用 `yichen-content-archive` 的读取脚本，正文和评论也可通过已授权浏览器读取；搜索、评论和主页等结构化读取按 `agent-reach` 的 OpenCLI／xiaohongshu-mcp／存量 CLI 路由核后端。详见[读取工具边界](references/platform-tools.md#读笔记正文评论与媒体)。这些读取后端需单独安装与认证，SAU 登录不通用；脚本拿到评论数不等于拿到评论正文，分析 Skill 也不自带后台数据。

凡实际支持话题或标签的发布入口，固定带 `AiGoodBro`，计入该平台总数。微博用 `#AiGoodBro#`，B站投稿标签填 `AiGoodBro`，小红书、抖音、TikTok、X、视频号用 `#AiGoodBro`；没有话题字段的公众号官方草稿、小程序分享入口不硬加。数量、格式及官方限制与制作预算的区别见[平台规格与话题](references/platform-specs.md#各平台-tag话题)，发布前核对最终落地。TikTok 的 CLI／MCP 与其他已安装入口统一见[发布渠道与工具](references/platform-tools.md)。

说“gbro ai短视频”进入[AI 短视频写作](references/ai-short-video.md)。围绕成片写简短标题与正文，先抓剧情、情绪或效果看点，再自然接到提示词、表情动作、镜头等具体教程内容和关注引导；保留你选定的标题与句子。沿用当前平台，单独写文案不自动制作视频或发布。需要先学习时实际看同类作品、教程和相关评论，按素材改写，不照搬别人的制作成绩或领取承诺。

用户新给的创作链接，未另作限制时，默认制作小红书和微博图文、按来源规则保留必要身份及话题、在当前授权允许时分组交飞书，微博核对账号、重复内容并取得适用授权后发布。任务中续给“再写一篇”的链接沿用当前平台、语言和交付阶段，各篇独立，不重新扩大平台。小红书只交素材，X 不自动发布；“只做某平台”“先给我审阅”“先不发”等当轮要求优先。不会自动补发历史链接或展开原文里的其他链接。

```text
使用 $gbro-social-workflow，把这条做成小红书图文，先给我审阅。
使用 $gbro-social-workflow，原帖和转帖一起核验，只做 X 和微博；另做一篇小红书工具精选。
使用 $gbro-social-workflow，定版：交正文、评论 Markdown 与封面内页，先不发送或发布。
gbro ai短视频：根据这段成片写视频号短文，保留我选的标题，结尾自然带一点教程引导。
```

先定本篇切口，再选体裁。趣味互动围绕原话、语气和直接上下文，图数按材料决定；资讯、教程、精选分别组织，不因为同一人物或产品就拼成大合集。“教程洗稿”按正文授权处理；“吸引关注”调整写法与图文分工；“继续/改这张”续接当前稿，“抓错重点”则同步修正受影响的正文、图片与评论。仅讨论或改 Skill 不启动制作、发送或发布。

“标题党”优先放大真实原话、反差、用途和结果，标题吸引点开、封面突出主题与证据、开头尽快兑现。要求学习高赞笔记时实际查看详情和评论，记录可见数据，也看普通表现与质疑；不能从评论数或几个样本推导算法和流量保证。案例留研究记录，可复用判断才写入 Skill。

能力路由、依赖与缺失处理见 [SKILL.md](SKILL.md)。教程、储存与品牌参考均在本包的 `references/`；外部工具、账户和人物原素材仍按实际环境定位。提示词不等于成品图。本包统筹原帖取材和视频制作，实际渲染、动效与配音调用现用视频工具。新制作视频默认竖向 9:16、至少 1080×1920；横片完整居中，上下黑色毛玻璃、淡蓝淡红缓慢晕染与轻微液态动效，字幕放下方，具体见[竖版视频上下包装](references/delivery.md#竖版视频上下包装)。软件／Skill／提示词／作品宣传片含片头片尾不超过 60 秒，主要交一条完整成片和独立封面，原片内部留存。片头片尾文案先确认，素材整理和中段混剪可先推进，详见[宣传片流程](references/delivery.md#skill-提示词能力宣传片)。Cheat 按原协议独立工作。

你给到 X 推文时，尤其 Tibo 的内容，使用真实截图保留原生帖子 UI、原作者头像、必要显示名、原话、回复关系与关键数字，将帖子整体框起来，局部去掉 X 标志、x.com 等平台标识和无关外层。保留原生阅读结构，不重画成另一套卡片；完整原图留本地核验，公开交处理后的图片。新加关键词强调仍只用直下划线。具体见[原生界面规范化](references/visuals.md#x-来源帖子的原生界面规范化)。

遇到“重置／reset”就检查原文与相关上下文，确认涉及额度或权益重置后直接写重置主题稿：未来安排写预告，投票或提议保留未确认状态，已执行则写重置消息。时间、范围和重置卡按证据区分，不编到账或全民重置；详见[重置消息识别](references/content.md#x-推文的重置消息识别)。沿用当前发送、发布授权。

给到推文让写时，会适当翻看评论区和作者回复，连同原帖或评论附带的贴题图片、截图、投票图和视频封面一起判断；挑贴题的接梗、有信息量的提问、反馈、补充或配图，自然写进正文，适合展示的也可做在图上，保留真实图片、评论界面、头像与回复关系。不固定凑数量，不把少数评论写成全体共识；没有合适评论或配图就不硬加。详见[评论区取材](references/content.md#原帖评论区取材)。

小红书和微信公众号成稿及配套评论均不放网址。每个涉及的仓库另交一句带纯文字 `所有者/仓库名`、必要前提、已核实安装或使用方法及最小验证的完整 AI 指令，同一仓库去重；含网址的实际命令留内部，公开评论用准确仓库标识和自然语言动作，不编命令。互动放正文，没有仓库的趣味稿不硬塞安装口令。当前对话直接交完整可复制正文、独立评论和实际成品图，用户明确要重发就复用当前验收版。规则修改直接维护现行正文；文件校验不代表所有生图、飞书或平台发布路径都已实测。
