# 飞书交付、维护表与公开发布

定版、交付、改文档、导出或发布时读取。素材发送、云文档更新、公开发帖分别按本任务授权执行。

## 定版对账

复用唯一作品目录和清单；正文与适用评论分别存 Markdown，封面及内页列图序，其他材料另列，交文件夹或清单入口。按平台/语言记录版本、文件路径、有序媒体、本地确认、飞书送达与公开发布结果，逐项读回。未生成、待确认、未发送、未发布分开，不把聊天展示当作已落盘。沿用已有命名、保留已交付旧版，共用媒体不复制。

储存细则用本包[储存规范](storage.md)，不另造竞争清单或空目录。先交已要求的小红书定版素材，再处理已明确授权的 X 等发布。修订差异单独说明；作品版本留内部清单或附带说明，不混入可复制标题、正文、评论，分割线也不嵌日期版本标记。

## Codex 机器人路线

在 `lark-channel-bridge` 中运行时，以当前注入的 profile、身份和会话为准，按当前 bridge 约定调用普通 `lark-cli`；不覆盖或移除 `LARK_CHANNEL*`、`LARKSUITE_CLI_CONFIG_DIR`，不套用下方独立桌面的机器人路线。目标会话按本轮发送要求确定，不把历史素材群当作默认接收方。遇到 channel context 未绑定错误，停止依赖该身份的发送，请用户重启 bridge 或运行 doctor/preflight，不自行 bind、读取账号密钥或改用普通 profile。

在 bridge 当前会话请求稿件或配图时，直接把本次完整可复制文字和成品图交到当前对话，不只交文件链接或说“已写好”。标题、正文、话题直接展示，安装评论另放可复制块。imagegen 的工具展示、本地保存和上传不等于飞书图片送达；按当前绑定身份实际发送成品图，并按消息 ID 回读。此会话交付不扩大到其他接收方或公开发布。

非 bridge 环境须由使用者配置自己的命令级 profile、bot 身份和接收方；不能继承作者的机器人身份。素材会话从已确认配置或可靠回执定位；包内不携带私人会话 ID。

按 `lark-im` 当前接口发送，先核实身份和接收方，不切全局 profile、不打印或复制凭证。其他机器须确定当地身份及接收方，不能套本机路线或个人授权。

## 每篇、每个平台独立成组

内部按“主题 × 平台 × 版本”对账；每篇每平台独立一对首尾分割线，标主题与平台。优先一条图文放齐必要文字和成品图；多条时用同组分割线夹住内容，避免穿插。

默认发送：

1. `------分割线起点｜小红书｜主题----------`
2. 可复制标题、正文及本次话题，内部说明不混入。
3. 按内容类型附独立评论：小红书、公众号涉及的每个仓库均按[口令要求](#仓库标识与安装口令)另交一句可复制安装或使用评论；同一仓库在本平台稿中去重。其他软件或 Skill 介绍、安装教程按需要给准确名称及前提，不编命令；实际无需安装的工具稿给具体用法。趣味互动只附贴题接梗或问题，资讯仅在有必要时附使用建议。出现产品名不等于安装教程；用户明确不需要评论时省略。
4. 按确认图序只发送按本篇设计语言包装好的成品图或本次明确要求的其他成品媒体；用户提供的原始截图留本地核验，不发飞书。只有用户后续明确改变这条要求，才发送原件。
5. `-----分割线收尾｜小红书｜主题｜已交项目与缺项----------`

来源、资料包、参考原图、旧版、图片提示词、执行记录及独立稿件文件留本地；原始截图不随成品图自动发送。X/微博成稿内必要原址仍保留；不发资料包不代表省略内部核验。多平台不混成“推文/微博配文”。

已有飞书授权且补图/重做时，一张验收好发一张，标主题、平台、图序并更新同一清单中的版本及回执。首次组图按整组交付，不扩成逐张公开发帖。

纠正分组或漏项时沿用当前授权补齐；用户纠正切口导致整组重做时，按当前正文、配套评论和完整新图序交付，单独说明替换哪组，保留旧消息与回执作历史，不混用旧角度的图片或指令。只改局部则只交受影响项。响应不确定先查回执，不直接重发整包；用户明确要“文字内容/重新给我/重发这两张”时，直接展示完整当前文字或按原序重发所指已验收成品，不因已有成功回执拒绝重发，不无故重新生图。重发使用新的幂等键并记录本轮回执。分割线以连字符开头时用 `--text=<值>` / `--markdown=<值>` 绑定，避免被解析为 flag。

发前核标题、正文、口令、媒体、分割线；发后按消息 ID 回读目标会话、发送者、类型、全文、图片数量及图序。PDF 等文件还要回读附件显示名，读者版文件名不带内部版本字样。上传不等于发送。单条已有首尾就不另发收尾，分条则最后发收尾并回读。记录回执与幂等键，后续只补缺项；不同教程 PDF 分组发送，不以第一份送达代替其余附件。

## 视频清晰度与完整交付

凡准备对外发布的视频，都从最终成片提取一版缩略图总览，按时间顺序排列，覆盖开场、关键动作、转折和结尾；默认采用本次确认的 4列×3行拼图，长视频可按内容增加帧数。总览使用真实视频帧，不用重绘图替代。将总览图片与完整提示词、各平台标题和发布文案、封面、压缩视频一起保存到该视频的飞书发布资料文档；文档链接写入既有飞书总导航，查重后新增或更新。已有明确交付授权时沿用；上传后回读核对图片和附件实际存在。总览辅助浏览，不替代独立封面或完整视频。

完整制作任务逐项对账：可复制正文、配套评论、视频、独立封面、需要的配音，以及实际工具和素材/配方说明。视频与封面直接发送到当前授权会话，不能只交链接、只给缩略图或让用户自行寻找历史消息。完整原视频与零散素材默认留内部存档，只有明确要求时才另交；无原视频时制作能兑现本篇内容的成片，不能用随意静帧、短小机制演示或提示词冒充完整演示。简化演示仅明确标为预览或机制演示，不算原项目实测。

AiGoodBro 品牌预设的多效果、艺术风格和工具演示视频默认做展示 Skill／提示词能力的精华混剪：每个效果取一小段，选多个彼此不同的片段，优先展示最吸引人的效果，按节奏衔接并配背景音乐；不把每个效果各做一条长片，也不只重复同一种效果。片段长度按动作是否完整、效果是否可辨决定，音乐与画面切点配合，有口播时压低背景音乐。最终以一条完整混剪成片交付，原片内部保留，下载或高清分段不能代替所需混剪；不凭“更吸引人”宣称实际传播效果。

画质优先保留来源分辨率和细节；AiGoodBro 品牌预设的 16:9 原片按[竖版视频上下包装](#竖版视频上下包装)等比完整居中放入 9:16、至少 1080×1920 的画布，不裁掉关键内容、不拉伸。其他新制作视频沿用默认横向 4:3、至少 1440×1080 或当前明确画幅；原片存档保留原画幅。外部 Skill 或模板的默认比例不覆盖本规则。源素材更低时说明限制，不靠放大宣称变清晰。原视频、高清主文件与传输版分别记录；传输版清楚标注实际分辨率和压缩情况，不能将低码率压缩版称为高清原片。画面轨完成、配音完成、飞书送达和公开发布分别验收。

先核当前接口实际容量限制，再决定传输路线。长视频不能为了塞进单条消息一味降至540p或极低码率：优先能保留质量的文件交付渠道，或按内容边界分段保持高清并标连续编号、顺序和完整时长。需改变接收方、分享范围或增加收费服务时沿原授权边界处理，不自动扩大。确实只能发压缩预览时明确其用途，同时保留高清主文件，高清未送达必须列为缺项。

原片重下先核最高分辨率/码率变体、实际文件哈希与解码；新旧哈希一致时先排查传输压缩，不反复下载。无损分段用stream copy保留画面码流，逐段核尺寸、时长、大小和连续范围；视频按媒体类型发送，不能把MP4视频上传类型与普通文件消息混用。正文和媒体参数互斥时分条交付，并回读每条。

代码动画先做短段渲染和资源预检，再跑全片。字体加载或GPU读回阻塞时在任务自己的wrapper调整系统字体/软件渲染，不改原库；记录替代范围。favicon 404与真实场景/字体失败分开判定，不能把部分上游QA说成全场景通过。

编码后核对时长、尺寸、音轨、帧率和可解码性，并目视比较来源与交付版的对应画面；至少看字幕/小字、复杂纹理、快速运动和多个效果切换段，在接近手机实际播放尺寸下检查压缩块、拖影与可读性。指标合格不代替画质检查；升码率、加分辨率或上传成功均不代表用户验收。不能通过完整解码检查就声称清晰。

配音按AiGoodBro 品牌预设要求使用剪映，核对实际音轨、可听内容及画面同步后才交有声成片。GUI 获取超时只证明连接失败，不证明应用不存在、用户未登录或缺权限；不得把其他合成音冒充剪映配音。工具失败先查实际任务状态，避免重复输入、发送或生成。缺项只阻塞对应环节，先交可用文件并准确标注无声/预览，继续保留待办。

工具、插件和模型名称先核对已安装入口及实际可调用接口；未知名称不凭语音相似自行替换。披露实际执行路径，区分读取配方、自写代码简化演示、完整原仓库运行与真实插件调用。用户要模拟调用时可以制作明确的模拟演示，不虚构调用日志、运行状态或完成证据。

### Skill 提示词能力宣传片

适用于AiGoodBro 品牌预设的软件／Skill／提示词／具体作品宣传片；其他视频任务仍按当轮范围执行。片头片尾文字待确认时，继续已授权的素材整理和中段混剪，只暂停依赖文案确认的制作。

1. **先整理来源素材。** 收到推文后，核对原帖、引用和相关回复，提取图片、视频、提示词及工具信息。发现视频时必须完整下载，检查清晰度、时长和可播放性，原片留作内部制作素材。
2. **先判断本期介绍什么。** 根据软件、Skill、提示词或具体作品，确定本期最值得展示的能力。名称、数量、效果和用途只按实际资料填写，文案随本期内容调整。
3. **片头使用液态玻璃介绍卡。** 采用简约的苹果宣传风格；玻璃框展示准确名称和一句贴合本期的介绍，必要时补真实数量或一句话用法，保持短而清楚。片头文字先作为候选文案交用户确认，再进入制作。
4. **按素材选择中段制作方式。** 有视频就选不同效果做精华混剪；只有图片就用动态构图和转场展示；有提示词但没有视频就实际复现。缺提示词时先补找，必要时按已授权范围补写后实跑，并明确标为自拟或改写。作者演示、本机复现和图片动效分别核实，不把其中一种冒称为另一种。
5. **让镜头和动效服务内容。** 先读取现用 `zzsy-dir-skill`／帧帧上影规则设计镜头，明确每镜的单一任务、可见变化和切点；液态玻璃读取现用 `u玻璃`，`S动效插件`（简称 `s动`）按现用 `video-use` 入口调用，配合制作适合的转场和液态玻璃效果。保留必要留白，让效果和信息清楚可见，音乐、切点与动作相配。若工具不可调用，报告缺项，不冒称已调用。
6. **全片持续轻量品牌水印。** 复用 [AiGoodBro 卡通人物参考](aigoodbro-character.md)，人物下方严格写小字 `aigoodbro`。根据画面选择角落，避开小红书 Logo、字幕和主体；遮挡时只调整位置或缩小，不删除水印规则。
7. **片尾按本期资源写，并先确认文案。** 片尾用简洁动效收束。介绍 Skill 时围绕用途和获取方式，介绍提示词时围绕提示词；涉及重置消息时才写相应提醒。关注口号、片头文字和片尾文字先交用户确认，确认后再制作；未确认固定 slogan 时只写本期候选，不说成既定口号。
8. **最终交付一条完整成片。** 宣传片含片头片尾不超过 60 秒，16:9 原片按上下黑色毛玻璃规则包装成 9:16、至少 1080×1920；其他新制作视频沿用默认横向 4:3、至少 1440×1080 或当前明确规格，并另交独立封面。原片和零散素材留内部存档，不把零散文件当主交付。压缩方式等成片完成后再核对，压缩版与高清主文件分别标注。飞书交付按当前授权发送完整成片和独立封面，并回读实际附件。

本类宣传片仍须把提示词、来源、性质和成功输出一一对应；提示词资源按[读者所得](content.md#读者所得)交可复制内容及用法。未真实跑出的候选不作为效果素材。60 秒上限仅用于本类宣传片，不套用于原视频或其他视频任务；不固定镜数或单镜时长。需要加入主页时，只放已核实为用户用户的小红书主页，不猜链接。

## 竖版视频上下包装

本节仅规定采用 AiGoodBro 品牌预设包装 16:9 原片的方式；其他比例按当前要求，不自动套用本节。包装前先读取本节与 [image-style.json](../assets/image-style.json) 的 `video_9_16`、`video_packaging` 和 `black_glass`，将最终画幅、中央原片位置、上下材质与字幕位置写入当前制作记录；不能仅因历史成片或封面是 4:3 就沿用横版视频模板。

- **画布与原片：**16:9 原片的包装画布为 9:16、1080×1920 或更高同比分辨率。原视频等比完整放在画布中央，上下剩余区域用于包装；保持操作界面、人物和原有文字可见，不裁切或拉伸主体。原生竖片保持完整可视，不为套横片模板强行缩成横窗。当轮明确指定其他比例时按当前要求。
- **上下背景：**使用黑色毛玻璃；黑底下只有淡淡蓝色、红色柔和晕染，配缓慢、轻微的液态玻璃流动与薄高光。颜色和透明度复用 `black_glass`，模糊和玻璃效果只作用于新增包装，中央原视频保持清晰。不得用白底、纯黑硬边填充或大面积高亮红蓝块代替已确认的质感。有已确认的包装设计或制作源时优先复用；私人样片不随分发包提供，缺失时按上述预设制作并完成当前任务所需审阅。
- **文字与品牌：**上方放本篇标题和必要说明，下方留给中文字幕、双语字幕及少量补充信息。新增字幕优先放下方玻璃区，避免覆盖原片；原片已烧录的文字不擦除、不据此重绘画面。字体、字号、行距、字距和边距用 `video_9_16` 固定预设，品牌沿用既定 AiGoodBro 人物和字标，避开字幕。重置消息的开场第一句话仍先写日期、具体时间和时区。
- **视频与封面分开：**9:16 是成片画布，不改写小红书 4:3 视频封面或其他平台独立封面的规则；封面按[平台规格](platform-specs.md#封面制作)单独制作并检查裁切。
- **预览与审阅：**复用已确认包装时直接按当前任务推进，不重新询问比例或颜色。新包装先做可播放的短预览并检查动效与字幕；用户说“给我审核／先不要合成整片”时，先交短预览，等待该节点通过再合成或发布，不把旧的发布授权当成本篇审阅通过。仅更新 Skill 不触发视频重导出或发布。
- **成片检查：**核对真实编码尺寸为 9:16，检查首、中、尾和字幕切换画面、上下玻璃与缓慢红蓝晕染、手机观看可读性、全片可解码以及音视频时长。只加包装的任务保留完整原视频、原声和内容；剪辑或配音仅按当前范围处理，不因默认配音流程覆盖原声。静帧不能证明动效或播放正常。

## 飞书维护文档

指定原链接就更新原文档。先 `lark-doc +fetch --detail full` 保存现状和引用，再按差异用 `str_replace` / `block_replace` 改相关区段；正文 XML 和样式遵循当前接口参考，无需全文重建时不用 overwrite。

工具合集默认：

1. 通俗标题、更新日期、一句阅读提示；更新日期是内容维护信息，不是 Skill 版本。
2. **一张总览表**：平台｜免费权益｜模型/能力｜期限与限制｜网址。序号并入平台列，国内外版分清，必要时分段或分行。
3. 表后仅必要的隐私、领取、计费提醒，通常两条；不追加分平台长文、运营话术、来源长名单或正文图片。

灰色表头、关键数字加粗、顶部对齐，按内容设列宽，可用轻量蓝色提示框。网址在相应平台末列，用短而准确的文字锚点；获准邀请链接标“邀请”，缺失链接只记本地待办，不上线假占位。

每轮结构修改后重新 fetch、用新 block ID；验一张表、平台和网址对应、最新模型与时限、无正文图片及提醒数量。颜色被 API 转成 RGB/RGBA 时按实际含义核对，不为字符串不同重写。

服务端内容/样式回读不等于浏览器目视；页面打不开就说明验证范围，不反复改正确文档。打开超时先查标签状态，避免重复页。用户要 Word/网页时复用同一核验数据，保持链接和版本一致，实际渲染才报排版通过；导出成功不替代原文档更新。

## 新建文档的分享权限

AiGoodBro 品牌预设已授权后续新建的对外内容文档默认“互联网获得链接的人可阅读”。完成后用 `lark-drive` 当前权限接口设置并回读，报告实际结果。仅阅读，不开放编辑，不扩至私人资料、目录或未经要求的既有文档。先读权限和 schema、不猜枚举，租户或文档限制不绕过。

### 仓库标识与安装口令

小红书、公众号稿中涉及的每个仓库均另交一句可复制评论，同一仓库去重；其他渠道的软件或 Skill 推荐按需要另交。评论是一句能直接交给 AI 的完整安装或使用指令，开头写核实的纯文字 `所有者/仓库名` 和项目或 Skill 名；作者昵称、外号和“上面那个”不能代替定位。小红书和公众号评论均不带网址、域名、二维码或个人机器路径，单独复制也能使用；评论按对应平台独立交付，不混进文章正文。

先按仓库当前 README、实际 `SKILL.md`（如有）和安装或使用文档核对，再在句内写清必要依赖、安装或使用动作、首次运行准备和最小验证，不能只给仓库名或安装器名。存在已核实且不含网址的适用命令时可保留；命令含网址时，公开评论改用准确仓库标识及“按该仓库当前文档完成……”的自然语言 AI 指令，实际命令与来源留内部，不删改命令里的网址冒充可运行命令。命令随读者的系统和当前 agent 目录调整，不编通用脚本；资源目录按实际用途给使用指令，不伪装成可安装 Skill。已有同名安装先比较，不自动覆盖；只有本机文件时说明需要完整文件夹，不编公开入口或换装同名项目。制作评论不授权本机安装、收费调用、发送评论或发布仓库。

使用口令另写清工具或 Skill 名、所需输入、具体动作和预期输出；已有环境或无需安装的功能给开启或调用方法，不能拿调用模板代替新读者的安装口令。

发前实际统计整句字符数，英文、空格和标点都计入；按用户或当前输入框上限压缩并留余量。用户反馈“超出若干字符”时，用现稿实测长度推算并核对上限，不把超出量当作上限。优先删客套和重复解释，保留仓库定位、必要依赖及命令、验证要求；不拆成多条让读者拼接。

可复制口令只放一整句，与标题、字数说明、过程说明和互动问题分开。完整重发按[分组规格](#每篇每个平台独立成组)带齐适用评论；局部超字数只改所指口令。渠道规则按AiGoodBro 品牌预设要求执行，不保证平台审核结果。

## 浏览器和发布

先按[发布渠道与工具](platform-tools.md)选择当前入口，并核[平台规格、封面与话题](platform-specs.md)。使用浏览器时按 `browser-skill` 或当前环境的专用浏览器工具建立有边界会话，读新状态后操作；用户指定的浏览器优先，独立扫码登录不改变发布浏览器限制。只有用户要求对标才研究其他帖子，局部修图不重启全网研究。

用户新提供的创作链接沿用主入口的[默认流程](../SKILL.md#用户链接的默认流程)：按当前授权决定是否发布，默认交付本地素材，其他平台不自动扩展。先审阅、暂停和当轮平台限制优先；这一默认不省略身份核验、去重、内容验收及发布回读。来源作者的跨平台对应关系只留在内部核验，不猜测账号，也不将账号提及带回公开稿。

编辑已有草稿、更新已发布帖子、补缺稿、引用转发或遇编辑器故障时，再读[平台编辑细则](platform-editing.md)。公众号、微博文章与其配套发布动作分别核对，群发、定时和额外设置依当前授权，不从一次发布推定。

发布前核当前账号、平台、最终标题/正文和有序图。邀请码、活动权益等本次指定值逐处核对，不能沿用源帖旧值；用户只要教程推文时，正文聚焦可操作步骤，不盲加作者解释、营销口号或未核实的条件。身份正确就执行已授权发布，不追加例行确认；新审阅或等链接条件继续有效。用户明确“没有别的链接/已经补齐”才恢复仅因该条件暂停的已授权发布，不靠普通“继续”推定齐全。

先比目标已有帖子/草稿，相同则跳过重复提交并继续其他交付；点发布后结果不确定，先查主页或帖子，不直接再点。

发布后取可读帖子或结果页，核标题、正文、图片、用户链接及账号，分别保存实际帖子链接。草稿、上传、按钮点击不算发布。登录、验证码、权限障碍只暂停相关动作，按工具规则请求必要人为步骤，不绕限制。
