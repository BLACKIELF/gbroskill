# 发布渠道与工具

发布前同时读[平台规格与话题](platform-specs.md)和[交付与发布](delivery.md#浏览器和发布)。本页规定工具选择，不扩大作品、平台、账号、群发或浏览器授权。

## 名称与能力层级

小红书当前发布工具是 [social-auto-upload（SAU）](https://github.com/dreammis/social-auto-upload)，命令行程序叫 `sau`，本机统一入口叫 `gbro-publish xiaohongshu`，操作说明 Skill 叫 `xiaohongshu-upload`。本流程没有把它注册成“小红书 MCP”。读取正文、评论和媒体另有[取材入口](#读笔记正文评论与媒体)，不能因 SAU 不提供读取就说整套 GBro 不能读，也不能把别的工具能力算到 SAU 身上。

Skill 是操作说明，CLI 是执行程序，MCP 是提供给助手调用的接口，`gbro-publish` 是转发到这些程序的本机包装器。安装 Skill 不代表安装运行环境、完成登录或接通 MCP。可调用的工具名也不证明目标平台已经绑定、账号具备权限或作品已经发布。

工具边界按「名称与来源、实际入口、支持的内容与字段、登录与身份、外部写入、缺失能力、验证证据」记录。复核已安装版本的 `--help`、必要源码和实际返回；发现新边界时直接修正本页，并同步已有 Obsidian 渠道笔记。账号快照、日期和版本留在运行记录与更新说明，不固化成 Skill 的跨账号默认。

## 选择入口

优先复用已接入的官方接口；当前账号无适用接口时使用已安装、可验证的上传工具或指定浏览器。官方分享 SDK、填稿、上传、提交审核、公开可读是不同状态，不能用前一状态宣称后一状态完成。

| 渠道 | 入口 | 实际能力与边界 |
|---|---|---|
| 抖音 | `gbro-publish douyin`，`douyin-upload` | SAU 创作中心扫码、校验、视频和图文；`upload-*` 会提交发布，不能当草稿测试 |
| TikTok（国际） | 已绑定账号时可用 `Metricool`；本机 `gbro-publish tiktok`、`gbro-publish tiktok-mcp`，`tiktok-upload` | Metricool 先核品牌、TikTok 连接和权限，再按其工具排期；本机 GitHub autotok 使用独立 Chrome 登录、校验、发布和定时，MCP 使用 stdio。上传会真实发帖，默认公开，没有草稿测试；不能用“美国 TikTok”推定账号地区或权限 |
| 小红书 | `gbro-publish xiaohongshu`，`xiaohongshu-upload` | SAU 创作中心登录、校验、视频和图文；默认立即提交，`--schedule` 定时，无草稿开关；标题、正文、话题和视频封面按下节逐项核对 |
| B站 | `gbro-publish bilibili`，`bilibili-upload` | SAU 调用已安装 `biliup`，支持登录、校验、单视频投稿、封面和定时；当前包装命令没有自制/转载及来源参数，不能保证准确处理转载稿，见下方字段缺口 |
| 视频号 | `gbro-publish tencent` | SAU 视频号助手登录、校验、视频、定时与双封面；默认真实发表，显式 `--draft` 保存后台草稿；保存草稿也会上传素材。合集只选已存在项目；审核状态与公开状态分开 |
| 微博视频 | `gbro-publish weibo-video` | SAU 视频上传和发布；必须提供封面与按事实选定的原创/二创类型；内容声明不自动代选，保留平台强制校验 |
| 微博普通帖／头条文章 | `baoyu-post-to-weibo`；普通帖为 `gbro-publish weibo`，文章为 Skill 内 `scripts/weibo-article.ts` | 两个脚本都只填编辑器，不完成最终发布；普通帖可带图／视频，文章接收 Markdown。包装器没有文章子命令，不能把 Markdown 路径当普通帖正文直接发出；视频主通道另用 `weibo-video` |
| X 图文／视频 | 已绑定账号时可用 `Metricool`；本机 `gbro-publish x`／`gbro-publish x-video`，`baoyu-post-to-x` | Metricool 按已核实品牌和套餐能力排期；本机脚本默认预览，`--submit` 才提交，视频处理完成后才允许提交。排期和脚本成功日志不能代替帖子回读 |
| X 长文章 | `baoyu-post-to-x/scripts/x-article.ts` | 安装包内有 Markdown 文章脚本，默认草稿，`--submit` 真实发布；包装器没有 `x-article` 子命令。先核账号文章权限及图片完整性；普通 X 登录不证明文章能力可用，不自动购买会员 |
| YouTube | 账号连接后复用 `Metricool` | 先核频道身份与连接权限；支持普通视频／Shorts 排期，必须提供视频、标题与是否面向儿童的选项。账号连接状态单独核实，不以工具列出 YouTube 代替已绑定 |
| 微信公众号 | 已接入的官方通道，`stylewx-article` 排版 | stylewx 的 `publish_draft` 写草稿箱，不是公开发表或群发；复用现有素材／草稿接口，正式发布权限另外核验，缺权限时保留已读回的草稿并走已授权后台入口，不重复接入另一套密钥 |
| 小程序 | 现有官方通道 | 只处理本次明确授权的内容同步；小程序不是通用社交发帖入口，不因“全平台”自动改代码、提审或发布小程序版本 |

本包运行入口为 `runtime/bin/gbro-publish`；依赖及配置说明见同仓库 `docs/INSTALL.md`。安装 Skill、安装运行环境、账号登录和发布成功分别验收。

## 操作边界速查

| 动作 | 实际影响 | 验收边界 |
|---|---|---|
| `--help`、`doctor` | 读取本机命令、依赖、账号文件状态和旧核验记录 | `doctor` 不联网续验；`not_checked` 不等于失效，文件存在不等于已登录 |
| `login`、二维码登录 | 打开官方登录流程并保存或刷新本机会话 | 用户完成扫码／必要验证；登录会写凭证，既不是只读检查也不是发布 |
| SAU `check`、TikTok `accounts check` | 联网验证已有会话 | 有效会话不证明平台显示身份、地区、所有投稿字段或实际发布成功 |
| baoyu 默认填稿、视频号 `--draft`、stylewx `publish_draft` | 填远端编辑器、上传素材或保存远端草稿 | 都可能把内容传到平台，不能当纯本地预览；公开状态仍未完成 |
| SAU 默认 `upload-*`、TikTok `upload`／`upload_video`、X `--submit` | 提交真实作品；视频号仅显式 `--draft` 为草稿分支 | 不用上传做连通测试；`--headed`、`--headless`、`--debug` 都不是免提交开关 |
| `--schedule`、Metricool 创建／更新排期 | 创建或修改会自动执行的真实排期 | 已排期不等于已公开；时间、时区及去重需单独核对，未经要求不排长期日历 |
| Metricool 送审工具 | 创建／修改送审状态，并通知外部审阅人 | 仅按用户指定的审阅人和送审要求调用，不当一般保存或测试 |

已有对应作品与账号的明确授权持续有效，必要修复和重验不要求重复确认；用户当轮“先审阅／先不发／只用某浏览器”等限制优先。无结果或结果未知时先查远端，不能靠重复提交探测。表内“有此能力”来自当前命令和源码，不等于所有分支已在真实账号发帖验证。

## 小红书的具体边界

| 命令 | 可传内容 | 行为 |
|---|---|---|
| `login --account <别名>` | 本地账号别名 | 生成或刷新独立会话 |
| `check --account <别名>` | 已保存会话 | 返回 `valid`／`invalid`，不返回完整账号身份 |
| `upload-video` | 单个 `--file`、`--title`、`--desc`、`--tags`，可选视频封面 `--thumbnail` | 不传 `--schedule` 即立即提交 |
| `upload-note` | 多张 `--images`、`--title`、正文 `--note`、`--tags` | 不传 `--schedule` 即立即提交；没有视频封面参数 |

两个上传命令的定时格式是 `YYYY-MM-DD HH:MM`，时区及平台可选范围临提交核实。当前命令没有 `--draft`／`--dry-run`；调试模式也不能替代草稿。填入话题时传逗号分隔的词，不伪造平台内部话题标记。

AiGoodBro 品牌预设小红书固定 **10 个不重复话题，包含 `AiGoodBro`**；AI 短剧类按[四个固定项](platform-specs.md#ai-短剧类固定话题)加 6 个贴题话题。CLI 拒绝超过 10 个，但这不等于程序自动保证“正好 10 个”和品牌项，执行者仍需核已选候选和最终数量。指定封面、标题或话题未成功落地就处理后再提交，不静默截断、换图或减数。

当前 SAU 上传入口未提供笔记搜索、评论读取／回复、点赞关注、已发笔记编辑／删除、账号数据分析；取评论或看已有笔记按下节选择读取工具或浏览器。这些能力不能从“能发小红书”推导。上传返回 `submitted` 没有自动取得可核验的公开作品链接，仍需去作品列表／主页回读。此路线依赖创作中心页面，网页变化、登录失效或验证弹窗可能中断，不能承诺永久无人值守。

## 读笔记正文、评论与媒体

先区分用户要搜索发现、读指定正文、看评论、下载媒体还是分析后台数据，再选入口。`agent-reach` 是读取路由说明，SAU 是发布程序；两者登录、安装和验证结果不能相互替代。读取能力按以下实际依赖单独验收，不因 Skill 中列了命令就声称已经接通。

| 读取入口 | 可读取／处理的内容 | 前提与边界 |
|---|---|---|
| 已授权的浏览器控制；历史流程见 `browser-skill` | 实际页面可见的笔记正文、作者、图片、可见互动数、评论与楼中楼、搜索结果和主页 | 以当前宿主允许的控制接口及用户指定浏览器执行。`browser-skill` 的 bsk 依赖 CLI、扩展和会话；当前宿主限定 CUA 时用 CUA，不把旧命令当作可用接口。页面未加载或未展开的内容不能当已读取；截图不等于原图下载 |
| `yichen-content-archive/scripts/xiaohongshu_fetch.py` | 用户给出的或已确认的单篇笔记 URL；解析标题、正文、作者、话题、页面可见互动数、图片／视频／字幕地址；另获下载授权后保存相应媒体 | 默认匿名；`--skip-media` 只保存 HTML 和元数据，不下载图片／视频／字幕，但仍会写本地文件。没有关键词搜索和评论正文抓取；评论数不能当评论内容。`meta_fallback` 可能只有摘要／封面，不能冒称完整正文或全部媒体 |
| `agent-reach` → OpenCLI 小红书后端 | 文档列出 `search` 搜笔记、`note` 读正文与互动数、`comments` 读评论／楼中楼、`feed` 推荐、`user` 公开主页笔记 | 需另有 OpenCLI、扩展和明确可用的 Chrome 会话，并获宿主允许；路由 Skill 安装不代表后端安装。不得静默替换用户指定的内置浏览器，也不自动导出浏览器凭证 |
| `agent-reach` → [xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) | 路由文档列出 `search_feeds` 搜索、`get_feed_detail` 详情和评论、`check_login_status` 会话检查 | 须实际发现服务和工具 schema、核登录后再调用；与 SAU 是不同项目和会话。详情需搜索结果中的 `feed_id` 和校验参数，不能猜 ID／参数。只选已授权的读取工具；不能把“读评论”扩大成发评论、点赞或发布 |
| `agent-reach` → 存量 xhs-cli | 文档列出 `search`、`read`、`comments`、`hot`、`feed` | 仅在本机确实安装且当前命令验证成功时用；存在历史停更和不稳定提示，不把文档里的命令当接通证据，不顺手安装 |
| `space-xhs-account-audit` | 根据主页截图、公开作品样本和已授权数据做账号分析 | 是分析 Skill；GUAIKEI／SocialDataX 等数据源、相关工具和额度另核。依赖名出现在说明里不证明已安装或付费；没有数据源时明确使用截图样本，不能编后台曝光或粉丝转化 |
| `space-xhs-note-analytics` | 分析用户自己账号的后台截图、CSV／Excel 或提供的数字 | 不抓取平台数据；正文、点赞／收藏／评论数不能替代后台曝光、点击率、完播等字段。缺失值不是零，样本不足不硬推因果 |
| `xiaohongshu-ops`（目录 `xiaohongshu-ops-skill`） | 提供搜索浏览、评论和运营流程说明 | 依赖 OpenClaw 浏览器 `openclaw` profile；不等于 Codex 内置浏览器或独立 MCP 已接通。跨宿主时先核可用工具，不能照搬固定 profile、旧话题数量或默认发布方式覆盖AiGoodBro 品牌预设规则 |

执行读取前，先查 `agent-reach doctor --json` 与所需后端的实际发现结果。Doctor 未发现读取后端，只说明这一路由未就绪，不能推导 SAU 不能发布或已知链接脚本不存在；`active_backend: null` 也可能只是没有实时验证。元数据脚本存在、浏览器已登录、真实正文已读回分别记录。

读取小红书时保留来源和采集时点；需要完整分享链接及 `xsec_token` 等校验参数的后端只在受控输入使用，文档与普通日志不展示敏感查询值，不猜参数或提取浏览器凭证。匿名脚本确需登录态回退时，按其既有目标授权和显式 `--use-cookie` 规则执行；安装／发布通道授权不能自动转换成其他工具的凭证导入授权。

评论必须区分可见片段、已展开楼中楼、分页已读数量、排序与截断状态；没有读取全部就写抽样，不把默认排序叫“热评第一”。作者评论、网友评论和正文分别标记，点赞／收藏／评论是公开计数，后台曝光和阅读量需真实后台或授权数据。取评论不发送回复、不点赞、不关注；下载不自动赋予转载或公开素材权限。登录、验证、删除或访问限制出现时保留已有结果，只暂停依赖动作。

X、微博、抖音、B站、YouTube、公众号也按相同分工：已知链接正文／媒体走适用的 `yichen-content-archive` 路线，搜索及讨论取材按 `agent-reach` 的该平台参考选择已装后端；发布仍走本页对应发布入口。已知链接脚本不自动扩到作者主页、推荐、评论或完整历史；没有字幕不等于没有语音内容，自动字幕也不等于人工校对译文。每个平台是否能读评论、字幕和下载都按真实接口单独核实，不能因路由覆盖该平台就承诺全部能力。

## 封面、声明和文章适配缺口

- B站包装器只传视频、标题、描述、分区、标签、封面和定时时间，没有传 `copyright` 或 `source`。涉及转载的作品，使用能明确设置自制／转载和来源的已验证入口；先核实际参数或网页字段，不把“工具上传成功”当作声明正确。当前包装器也不承诺动态、专栏或多分P投稿。
- 小红书等上游源码出现声明处理，不代表本机 CLI 已提供相应开关。AI、转载、商业内容等必须按本篇事实核实际表单；入口不能设置必需字段时只暂停这条提交，使用符合既有授权的可用入口，不让默认值代替声明。
- 微博头条文章脚本会处理超长标题／摘要：标题上限 32 字符、摘要预算 44 字符是当前脚本行为。先准备符合预算的确认稿，填后回读；不接受脚本截断或重新生成后未经核对的成稿。
- X／微博文章需核正文图片数、占位符和封面。日志出现“已填好”或自动预览不证明每张图完整；缺图或残留占位符时先修复。长文章脚本存在不表示它已并入 `gbro-publish` 或本账号具备文章权限。
- TikTok 本机 autotok 已接入视频与定时；独立封面上传尚未核实，商业参数 `brandorganic`／`brandcontent` 被上游忽略，不能把这些参数当作商业披露成功。Metricool 的网页选项也不能直接套入本机 autotok 或猜成 MCP 字段。
- 微信公众号官方接入需分别验收素材、草稿、发表和群发权限；权限错误不能靠反复提交修复。公众号的用户标签是用户分组，和文章话题不同，具体按[话题规则](platform-specs.md#各平台-tag话题)。小程序内容同步与代码上传、提审、版本发布分别处理。

## Metricool 连接器

Metricool 可通过当前工具读取品牌连接、读取／创建／更新排期、查看支持的数据指标与推荐时间；只用于用户已授权且品牌实际连接的渠道。先调用 `getBrandSettings` 核品牌 ID、平台账号和品牌时区，再读取对应时间窗口的 `getScheduledPosts` 去重。本机浏览器或 autotok 的登录不代表 Metricool 已绑定；“插件安装”“Metricool 授权”“平台账号绑定”“可排期”“实际发布”分别验收。

分析先用 `getAnalyticsAvailableMetrics` 获取当前可用指标，再用 `getAnalyticsDataByMetrics` 读取授权品牌的实际数据。指标目录支持某平台不证明该品牌已接入；没有数据不写成零曝光。推荐发布时间是建议，不证明自动化正在运行。

当返回没有任何社交网络连接时，记录待绑定并将工具返回的连接页面交用户完成官方授权；绑定后重新读取品牌。账号连接、付费套餐或额外权限不靠复制 cookie、修改全局认证或默认购买解决。没有显示的渠道不猜测支持，抖音、小红书、微博、B站、视频号与微信现有官方入口继续按各自工具执行。

- 所有支持话题／标签的渠道继续带准确的 `AiGoodBro`，按各平台格式与总数；连接器不会代替这项内容检查。
- TikTok 必须带图片或视频；媒体文件应使用工具实际支持的输入，不把仅本机可访问的路径冒称云端已收到。
- YouTube 连接使用频道所有者或品牌频道的 Owner／Primary owner；管理者权限不自动等同于 API 连接权限。频道绑定、Google 授权和发布分开验收。投稿先核视频、标题、描述、普通视频／Shorts 类型、受众、可见性和内容声明；只有网页明确提供的字段，不直接猜测 MCP 的 `info` 结构。连接与投稿说明见 [Metricool 连接指南](https://help.metricool.com/how-to-connect-youtube-to-metricool-tqiwo)和[发布指南](https://help.metricool.com/schedule-and-publish-on-youtube-gof0k)。
- 日期和时区使用明确的 ISO 8601 时间及读取到的品牌时区；用户明确时间优先，未指定时才按授权范围读取推荐时间，不自行创建长期排期。
- `createScheduledPost` 会创建真实排期。`plannerUrl` 是 Metricool 排期管理链接，不能当公开作品 URL。`getScheduledPosts` 只读未发布排期；列表里消失不证明发布成功，还需平台回读。
- `updateScheduledPost` 立即覆盖排期内容；先取完整原字段，只改用户要求的部分。更新后帖子 ID 会变化、UUID 保留，后续使用新 ID 或重新读取。
- X 通过 Metricool 按单条帖子处理，不擅自拆线程；长度权限以品牌与接口结果为准，报错原样说明，不自动改写已确认正文。
- 只有用户明确要求送审且指定审阅人时才用 review 工具。外部审阅人会收到邮件，不把送审作为连通测试，也不默认触发通知。
- 用户限定内置浏览器等发布入口时继续遵守；安装 Metricool 不自动解除该限制。超时或结果不明先查排期和平台，不能用另一条通道重复提交。

## 登录与账号

`--account AiGoodBro` 是本地凭证文件别名，不能证明登录了哪个账号。登录后核平台可见昵称及 UID、主页或账号 ID；只把非敏感身份信息记入作品清单，禁止输出或归档 cookie、token、验证码。校验返回 `valid` 只证明会话有效。

新上传器使用独立 Chrome 会话／profile，不能继承内置浏览器登录。用户指定内置浏览器时，安装、扫码登录授权不改变实际发布的浏览器限制。指定浏览器不可用，只停该发布及依赖步骤，继续制作、规格核验等独立工作，不静默改用 Chrome。

二维码、验证码和平台安全验证由用户按官方窗口完成；不替用户绕过验证。登录过期时仅重登该渠道。只重连或关闭本次启动且已定位到确切 profile/PID 的进程，不批量关闭 Chrome，不复制其他账号凭证。

安装运行环境后，抖音／小红书可由使用者在终端执行登录：

```bash
gbro-publish douyin login --account YOUR_ACCOUNT
gbro-publish xiaohongshu login --account YOUR_ACCOUNT
```

## 提交与回读

1. 核当前账号、定稿文件、标题／正文、封面、字幕、话题及原创／转载等字段；比较目标已有作品，跳过同稿重复提交。
2. 按当前入口核文件规格、处理完成状态和平台必填字段。明确要求的话题不能静默舍弃，候选失败先处理再提交。
   所有支持话题／标签的入口必须包含准确的 `AiGoodBro`，计入去重后总数；写法和数量按[话题规则](platform-specs.md#各平台-tag话题)，不能把其他平台整组话题原样搬来。若超上限，先精简其他话题并保留品牌项；用户指定总数与入口限制冲突时停在提交前报告。
3. 只提交一次。超时、弹窗、页面未跳转或脚本断开时，先查作品列表／主页；结果未明不得直接重跑上传或重复点发布。
4. 保存作品 ID、实际 URL（有才写）、账号、状态与回读时间；重新打开作品核媒体、字幕、封面和正文。只有审核中则记录审核中；没有可用公开 URL 时记录空值及已读到的列表证据。

## 安装与维护

安装前检查同名 Skill、CLI、现有官方通道和配置；已有适用能力优先复用。上游工具能力以固定安装版本为准，更新需备份、比较并保留本地规则。浏览器路径、声明选择、话题校验、重复提交保护及处理完成检查属于本机补丁，升级后逐项复验；不可直接用上游覆盖本地修正。

TikTok 的 CLI／MCP 先读 `tiktok-upload`；本机包装器核 `#AiGoodBro` 与最多 5 个话题的保守运行预算，后者不是已确认的全平台硬限制。MCP 配置样例在运行根的 `config/tiktok-mcp.example.json`，未自动注册到 Codex 全局配置；可直接用统一入口启动。会话文件、联网会话校验、平台身份核对和真实发布分别记录，不以安装成功或本地别名代替账号身份。
