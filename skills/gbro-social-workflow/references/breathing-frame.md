# 呼吸晕染边框

重置消息的主卡或视频内容卡默认选用本包装；用户提“流光包框”“流动包框”“重置消息那套”“iPhone 那套”或“呼吸晕染边框”时，复用本节已确认模板。多色光晕沿边流动并扩散、收回，矩形和源画面固定，不随呼吸缩放；保留青蓝、紫蓝、金绿、玫红的原色与 12 秒周期。光框中心透明，背景仍是独立、连续的 4 秒红蓝球面光线。其他品牌沿用自己的规范。

- **重置快讯来源卡：**可使用 [X样式重置消息模板](../assets/breathing-frame/reset-message-template.html)，按[重置消息规则](publishing-continuity.md#重置消息放最前并写短)填入本次真实作者、原话、译文和时间。
- **9:16 上下包装：**打开[竖版模板](../assets/breathing-frame/portrait-template.html)，选择本地视频、编辑上方标题，并加载已审字幕 JSON；空素材时不嵌入示例画面。具体矩形、透明层、字幕和导出按[竖版视频框与独立字幕](#竖版视频框与独立字幕)执行。模板不是已导出的成片，声音按当前任务处理。
- 以下为既有 **1920×1080 横版纯边框**，与竖版羽化模板分别使用：
- [纯边框播放器](../assets/breathing-frame/frame.html) 通过相对路径读取同目录 `loop.webm`，12 秒、1920×1080、30fps、VP9 alpha；双视频交接只显示一层，预载失败回退单视频。
- 默认源矩形为 x=320.824、y=90、宽=1278.352、高=900，单位为画布像素。播放器遮罩该矩形，保持内部透明；其他合成器使用该 VP9 视频时也须沿用精确源矩形遮罩，因为解码后的边缘 alpha 可能泄漏，不能仅凭裸 WebM 保证内部透明。适配 OBS 时浏览器源设置 1920×1080、30fps。模板不包含画面、头像或文案。它是无声透明包装素材，不是完整静音成片；不要给边框本身添加音乐，最终成片按其音频规则处理。
- 只有画布和源矩形匹配时直接使用现成视频。其他画幅或矩形须复制 [渲染源](../assets/breathing-frame/render-source.html)，调整 canvas 尺寸和 `sourceRect`，通过 `?rec` 打开渲染源，等待 `gbroVideoFrame.ready`，对帧号 0–359 调用 `seek(frame/30)`，输出 360 帧透明图并编码为 12 秒透明 VP9 WebM，同时同步调整播放器画布与遮罩；不要拉伸旧视频硬套。检查晕染未被画布边缘截断，必要时留足外边距。
- 验证首尾连续、矩形内部透明、光晕扩张与收回、叠加无闪白，再在目标播放器和 OBS 实际检查；源画面、文字和品牌素材按当前任务另行提供。

## 竖版视频框与独立字幕

- 成片 9:16，至少 1080×1920。此尺寸下，16:9 源窗口参考为 `x=44, y=657, width=992, height=558`；源画面、光框和遮罩使用同一矩形。其他源比例按实际显示比例等比完整放置并重排，不能拉伸到参考矩形。高分辨率等比例换算坐标、圆角、羽化和字号。
- 直接复用[竖版模板](../assets/breathing-frame/portrait-template.html)的 bloom 算法：30px 圆角、沿圆角轮廓的 12px 视频羽化、14px 光晕内侧衔接；光框中心完全透明，视频主体保持清晰。不要拉伸横版 `loop.webm` 冒充当前竖版包框。
- 视频框下留白新建独立中文字幕文字层，保留原片内嵌字幕；禁止裁切、放大或挪动小字幕图片冒充文字重建。此区域移除静态装饰副标题，不与动态口播字幕争空间。标题、头像、品牌字标、声音和四类尾板继承现有已确认规范。
- 1080×1920 参考：真实字体 `PingFangSC-Semibold`，72px，白字，无底框、无描边、无阴影；顶部居中锚点 `(540,1280)`，即源框下沿加 65px，安全宽 936px、两侧各 72px。源框移动后按其下沿重新锚定，通常不超过三行。CSS 字体名与 bold 不证明 libass 选对字体，核对实际 `fontselect`，不能自动换字体或缩字号。
- 按语义换行，英文单词不断开；闭合标点不行首、不单独成行，不删标点。超长句按语义分组并随音轨分时显示；校验组时长，避免不足 0.75 秒短闪，真实短尾句可与紧前句合并，保持原文字与对应声音区间。不得机械按字数分时后直接验收。
- 保存可编辑源 SRT 和排版 ASS。OCR 从原片硬字幕重建时，对邻帧与原图复核，合并同句碎片，排除界面英文；专名和中文句尾英文仍保留。不得把 raw OCR、猜补或摘要直接灌入字幕。检查漏识别空白、错字、尾句完整、全文及标点一致。
- 明确记录源时间轴、裁剪起点和开场偏移：`成片字幕时间 = 源字幕时间 - 源裁剪起点 + 开场偏移`，每个偏移只应用一次。按全片抽查同步、字幕切换、安全区和手机实际可读性；字体/字宽自动检查不代替目视。

已审 SRT 可用轻量[排版工具](../scripts/prepare_subtitles.py)生成 ASS 与预览 JSON（复用已安装的 Python/Pillow、fontconfig 和苹方字体；缺失时报告，不自动安装）：

```bash
python3 scripts/prepare_subtitles.py source.srt --output captions.ass --source-start 0 --intro-offset 0 --source-bottom 1215
```

命令从本 Skill 目录执行。默认输出为源时间轴；仅当直接烧到包含开场的整片才填写实际 `--intro-offset`。若先渲主片再接开场，保持 0，不能重复加偏移。HTML 必须选择与源 SRT 匹配、未裁剪且未另加开场的原片，再加载同名 JSON 预览；页面按原片 currentTime 计算上述映射。若加载已经剪辑或加开场的成片，必须先把字幕换成该视频的时间轴，不能沿用原片映射。原 SRT 与 JSON 都是本机输入，不上传。HTML 预览与 libass 字形度量、行高可能不同，最终以实际编码字幕的安全区、同步和手机可读性为准，不宣称两者像素一致。

透明光框导出继续复用现有 `gbroVideoFrame` 接口：打开竖版模板 `?rec=1`，等待 `ready`，用 `setRect({x,y,width,height})` 对齐源矩形，对 `n=0…12×fps-1` 调 `seek(n/fps)` 并只保存 `gbroVideoFrame.canvas`。24fps 为 288 帧、30fps 为 360 帧，不重复采样 12 秒端点。使用保留 alpha 的中间件（如 FFV1 `bgra`）；缓存必须绑定源模板哈希、画布、矩形、fps 与周期，不仅凭同名帧存在就复用。最终透明中心、边缘过渡和接缝仍按下节验收。

## 图文消息口播的图片框

图文消息口播全平台使用 9:16、至少 1080×1920，只有用户当次明确另定画幅时例外：首帧放完整主标题，真实来源截图、关键数字或差别与字幕按阅读顺序在竖版内重新排版，保持截图自然比例和手机可读性。截图的外框沿用本节多色呼吸晕染，保留模板原有青蓝、紫蓝、金绿与玫红的流动层次、12 秒循环和30px圆角；整页背景仍是独立4秒红蓝循环。每张截图按自然比例和实际外接矩形单独适配，不能把旧视频框拉伸套用。光晕放在图后，正文、头像和数字保持清晰，图片本身不呼吸缩放。静态导出封面可取同一动效时刻，不能把静帧称作动态成片。

每个关键内容组按最终编码画布核对实际外接矩形，不以文本居中或旧模板坐标代替：画布宽为 W、内容左边界为 x、宽为 w 时，中心必须为 x+w/2=W/2，左右边距 x 与 W-x-w 相等。截图、包框、标题及品牌组共同对齐这一中心线；组内文字可按阅读需要左对齐。纵向检查完整内容组的视觉重心与上下留白，在当前安全区内整体重排，不能只移动截图、沿用旧横版内边距或机械套历史顶距。实际成片逐场景抽帧核对，不只看 HTML 容器。

## 导出相位与循环验收

光框保持独立 12 秒无缝周期，背景保持独立 4 秒周期；相位按整条成片的全局时间连续推进，不能在每个镜头重新从零播放。同款预渲染循环源从第 0 帧解码，用 `-stream_loop -1` 延续，在滤镜内裁到目标相位，再把时间戳归零；不要在循环视频输入端用 `-ss` 设入点。相位必须在连续解码后的帧上计算，不能仅凭源 WebM 自身正确就认定合成循环正确。

固定 30fps 时，光框一周期为 360 帧、背景为 120 帧。优先用最终导出时间轴的累计整帧数计算相位；镜头开始于最终全局时间 S 秒时，分别计算 `round(S*30)%360` 和 `round(S*30)%120`，用 `trim=start_frame=计算出的帧号,setpts=PTS-STARTPTS` 处理对应输入后再叠加；不把 12 秒末帧重复编码成额外第 361 帧。更换帧率时先按实际帧率与周期换算，不照搬 360。

先用超过 24 秒的连续短片核对两个接缝，再核最终导出在全局 12／24 秒及后续接缝、场景切换前后的边框区域：颜色与扩散应连续，没有突跳、闪白、停住或相位重置。核对实际编码帧数、正常相邻帧变化与接缝变化，并比较多个中间相位的 t 与 t+12；内容或字幕变化不要误算成光框错误。`seek(0)` 与 `seek(12)` 相同可能只是接口取模，`-stream_loop` 参数或完整解码也不能代替连续播放验收。最终成片的循环检查通过后才替换旧版或把修复发布到共享模板包。
