# 教程洗稿

触发词：**教程洗稿**。用户给出教程链接、原文或本地材料时进入此分支。已有上下文中的目标、角色、风格和授权继续有效；不要重新问已确认的信息。

## AiGoodBro 品牌预设教程检查项

这是AiGoodBro 品牌预设反复确认的制作顺序，不把某篇 Muse 的数字、邀请码或标题复制到新题材：

1. 先读给定帖子、引用／转推所指原帖、完整教程与可用媒体，直接根据这些材料快速成稿。默认不查官网或同题资料；只有用户明确要求自行搜集、补全、额外搜索或核验时，才扩展到其他来源，并记录其贡献。原文保留模式只使用指定来源及同源媒体；不把作者的演示写成本机亲测。
2. 按[真实截图交付条件](visuals.md#真实截图是图文交付条件)为每篇教程图文取得对应实图，再判断是否直观。可用就以“新包装＋真实截图”讲解；英文界面按[中文译制规则](visuals.md#教程截图的品牌包装)处理，保留原图及产品名和 token 等术语。需要卡通人物的插画用已选无眼镜 AiGoodBro 角色和当前红蓝白配色重新生图，不直接沿用原作者或其他品牌的卡通人物；真实操作截图仍忠实保留，不能用卡通示意图冒充实机界面；来源为 X 时，帖头、评论、投票等帖子界面按[原生界面规范化](visuals.md#x-来源帖子的原生界面规范化)保留原作者头像与必要显示名，教程内的实际软件界面仍使用真实截图。新制品牌图按[当前人物与字标](aigoodbro-character.md)安排全身人物或半身头像，不恢复旧软件图标，人物不遮挡界面；除上述 X 原生作者栏外，改写后的公开成品默认不额外写原作者或“原教程截图”灰字，姓名、网址、原图和译制关系留内部。
   用户明确说“图片也要替换”时，逐张记录原图作用及替换结果：概念图、卡通人物和装饰图重做；清晰相关的操作截图以新包装进入成品，不把“替换”理解为抹去真实操作证据。原截图不适用时，选可核对的实际新截图；没有实图就记录配图未完成，不能用示意图替代成品中的真实操作证据。保留教学顺序，图片不能只换皮而丢失按钮、参数或结果。
3. 用户说“首页保持之前习惯”时，先看当前同类已确认成品。社交首图沿用对应平台的手机画幅、大字主张、真实界面与品牌层级；长教程 PDF 首页沿用下节 Muse 已确认的 A4 结构。封面写“教程”就要在内文兑现实际操作，不拿概念图或空泛口号凑页。
4. 长教程除正文源外制作可阅读 PDF，按原作品目录和版本管理；读者版去掉内部日期式版本字样。先验收封面、实际截图、分页、链接、二维码与全文，再按AiGoodBro 品牌预设已给的持续交付要求发送到既定飞书目标并回读；用户当轮指定先交哪份，就先交那份。小红书、微博、X 的公开发布分别核对授权与现状，飞书送达不等于平台发表。

## 先确定正文与图片的范围

- “教程洗稿”默认保留原文的事实、步骤、条件和教学顺序，对表述与结构快速重写，按上下文重做配图；不因改写自动扩展来源。“原封不动”“不要优化原文”“给我原教程”优先进入原文保留模式：先用已存原文和原图，缺项才回到**同一指定来源**补取；用户说“不要查询别的资料”时，范围仅含所给帖子、它指向的原文及同源媒体，不启动同题搜索、官方补查、事实重写、标题优化或营销改写。原文的标题、作者署名、第一人称、代码、步骤、图序和原截图都保留，除非用户明确点名要改；只可去掉平台界面杂项并为阅读排版。默认的改图、翻译、卡通人物、品牌首页、二维码与页脚不进入纯原文版；用户同时明确要求品牌包装时，可在不改教学正文和图序的前提下增加封面、页角或末页，并把新增知识放在独立补充章节。仅在用户要求两版时分别交付原文版与包装版，不能把编辑版冒称完全未改的原帖全文。
- 用户指定替换邀请码等单一字段时，锁定新值和替换范围，逐项核对公开正文、图中文字、截图衍生图、PDF 与发布稿；只改被点名的字段，不顺带重写价格、步骤或其他人的经历。内部原始来源与原图保持不变，保留旧值仅供内部溯源，交付成品不能残留旧值。截图中的可编辑输入值若需替换，另存衍生图并记录替换位置与方式；它不能再标作未经编辑的原始截图。产品事实、支付结果与不可编辑状态不为迎合新邀请码而伪造。
- 用户已说明其提供的素材均获授权：改写后的公开成品默认不写原作者，除非用户要求；作者名、自我介绍、署名、图片来源灰字按此约定清理，原始姓名、网址与授权记录保存在内部。明确要求保留原文时，原文自带的作者和第一人称仍照原样保留；实质性引用、技术名词和示例不能当作署名一起删掉，也不把原作者经历或实测改成自己的经历或实测。英文操作界面按视觉规则默认翻译，App名、产品名与token等技术用语保留。
- 图片可以按上下文重新构图和调整措辞；用户允许自由发挥时，选择更直观的表达。保留概念、数值、逻辑关系与对应段落，不能把图片改写许可扩大到正文。
- 链接正文与引用教程是不同对象；如果无法从上下文确定要哪部分，先厘清范围，再写入。不要默认把父帖案例、引用全文与回复全部混在一起。
- “先给我看，然后再执行”是该阶段的审阅边界。先交具体预览；用户选定或说开工后继续，已授权步骤不重复询问。

## 实际教程与无 GitHub 链接版

- 先识别帖子、长文章、引用帖与关联仓库的关系，读取实际结构，不因用户口头说“转推”就假定存在引用帖。上下文已明确目标时直接沿用。
- 用户要求纳入仓库内容时，读取教程章节、步骤、命令、配置、截图和案例，建立源章节与成稿的对应记录。介绍文章及资源入口不能代替实际教程；缺失章节明确记录，不用简介凑齐。
- 记录来源地址、取得日期和可取得的仓库版本。默认按原文表述时效内容及其前提，不把它改写成已独立验证的当前承诺；只有用户明确要求核验时才查当前资料。历史截图、操作模板与本轮实测分别表述。
- 用户明确要求“自行搜集／补全教程／搜索其他教程”时，继续搜索相关教程和实际案例；X 可优先筛选点赞、评论较多且内容相关的帖子，记录采集时间，互动量仅用于发现材料。仅要求“去重重梳理”时，在指定原文内合并重复内容，不因此扩源。英文按含义译成中文，保留前提与来源；按读者任务整理入口、步骤、示例和检查方法，而不是逐篇堆叠或逐句替词。这一明确授权覆盖本流程的默认来源边界，不强制用于“原文不动”的任务。
- 区分产品介绍、入门教程与完整教程：介绍也应让读者学到一个具体用法，教程须兑现承诺的操作深度。只要介绍时不堆进完整进阶手册；封面写“使用教程”时，内图应有真实步骤或完整任务模板。
- 用户要求“无 GitHub 链接版”时，读者正文直接给出可执行的内容，检查可见网址、图片及文档超链接，按指定范围去掉 GitHub URL；其他必要入口按当前要求保留。原链接、源文件与许可留在来源档案，删除入口不等于删除实质内容或必要归属。

## Word 阅读、链接与订阅文案

仅在用户要求 Word 时生成并检查文档。用户指定的二维码或引导截图放在最前面，保持完整；可配“获取最新 AI 资讯、实用工具和上手教程”等符合要求的引导，末尾按需要加入经核实、重新组织的 AiGoodBro 软件简介。二维码、联系方式和订阅引导不自动进入小红书公开素材。

- 蓝色字体不等于链接有效。需要跳转的文字建立真实超链接，核对目标；不能点击时在旁边附完整网址。用户要求网址同时可见时，即使可点击也保留；无 GitHub 链接版遵守上节范围。
- 有目录时检查内部跳转；检查实际渲染中的图文对应、换页、重叠与图片比例，保留软件核心区域。
- 修改已有 Word 前核对用户的现有编辑，合并已确认改动后同步正文源，不用旧源稿覆盖用户修改。局部变更优先检查变化部分；未变化部分可复用既有证据，并如实注明检查范围。

AiGoodBro 品牌预设的 AiGoodBro 系列教程涉及账号购买和订阅时，默认沿用下列已指定表述；当前要求优先。它是教程引导，不是对套餐、价格或供货能力的验证，也不是其他品牌教程的通用广告：

```text
购买账号和订阅，可以私信小助理，问问他有没有好的办法。如果有 Gmail 账号，也可以直接前往 aigoodbro.com 查找订阅方式。
```

需要网址同时可见时显示 `https://aigoodbro.com/` 并建立链接。保留影响使用的前提和费用区别；不把教程内这段引导复制到小红书公开文案、图片或评论。

## 长教程 PDF 读者版

AiGoodBro 品牌预设凡用 GBro 制作长教程 PDF，默认从本作品当前正文与已有配图生成，并将 AiGoodBro 二维码品牌页置于首页；纯原文保留版或用户明确强调不放时省略，原文加品牌包装则按明确要求制作。保存在原作品的交付目录，内部按 `MMDDvN` 递增并保留旧版。首页标题要准确写出实际产品、教程场景和关键型号，例如 Claude Code 与 Opus 5.5 要同时出现，不把某个模型名当作整篇教程的对象；首页还展示用户提供的 AiGoodBro 二维码原图、品牌字标和 `aigoodbro.com`。角色按当前讲解需要出现，不强制每页添加；需要时放小尺寸已选无眼镜形象，避开二维码、正文、页码并留足页边距。二维码不能用生成式图像重绘，导出后核对原图像素与可扫描性。当前用户提供的品牌页参考图（原私人参考未随包提供；请使用自己已授权的素材）用于排版和文字层级；可把原始二维码嵌入新首页，不必把参考图的主题无关活动原文逐字套用到每篇教程。

小红书配套的“xhs完整教程”版按用户当前约定单独制作：完整教学正文、原提示词和必要配图保留，全篇去掉二维码及“扫码”文案；原首页的订阅与小助理信息移至最后一页，首页只放教程标题与内容导览。用户要求保留的订阅信息不因去二维码而整段删除，也不带入小红书公开9图、正文或评论。文件完整名称和飞书附件显示名均须含精确字样 `xhs完整教程`；内部文件仍可按版本管理，读者页面与附件显示名不出现内部日期版本。该版本优先于上面的二维码首页惯例，不自动覆盖其他用途的旧PDF。

“首页沿用之前习惯”的实际排版参考是已交付的 Muse 云电脑教程 PDF（原私人参考未随包提供；请使用自己已授权的素材）首页：暖白 A4 底、上方大标题和一行蓝色学习收益、中央完整二维码原图、二维码下三行引导、右下小幅无眼镜卡通人物。新教程沿用阅读层级、留白和二维码位置，品牌署名使用当前人物／字标，不恢复参考页中的旧软件图标；替换主题标题及经核对的学习收益，不把 Muse 的 token 数字带入其他主题。社交平台的首图另按对应画幅和审核规则制作，不把 PDF 二维码首页直接当小红书封面。

二维码下方必须出现 AiGoodBro 品牌与 `aigoodbro.com`，网站文字建立实际链接。下列三行是用户提供的现有活动版式参考，可按当轮教程和经核实的活动情况优化表达；套餐、优惠、期限和价格不是永久默认项，不把该引导带进小红书公开图文、封面或评论：

```text
GPT AI订阅网站 aigoodbro.com
扫二维码有优惠 · gemini pro 18个月
（5-20浮动，反正也很便宜了～无需密码 给你网址开通）
```

读者可见的新封面、品牌页和页脚不显示 `0922v4` 一类内部版本字样或单纯的制作／更新日期；原文保留模式中的历史正文日期、教程步骤必需的时间、期限与条件按原意保留。来源网址、文件版本与历史交付状态只留在内部清单。用户要求每页有卡通形象时，在页边或右下角放小幅角色，逐页检查不挡文字、截图、二维码和页码；用户要求订阅宣传页放末尾时照做，不把该页塞进教程步骤，也不把某次活动自动套用到下篇。先检查可见文字、二维码、角色、封面留白、正文截图、原链接和分页，再看实际 PDF 渲染；仅改封面时核对正文页面未变。用户明确说不做图片哈希校验时，用原文对照、图序、逐页目视和飞书附件回读验收，不再追加哈希步骤。

用户指定“先给某份 PDF”时，先完成这份的本地验收，发送到既定飞书目标并回读消息和附件，再继续其他文件。其余已授权的教程按相同格式制作、单独归档和交付；飞书附件显示名不带内部日期式版本号。修订已发文件时另存新版本，更新飞书消息中明确以新附件为准，旧回执保留作历史记录。

交付每份长教程时，除 PDF 外同次给用户一段可直接复制的内容简介：用一段话说清教程适用场景、主要内容和读者能完成的操作或判断，必要时点出使用前提或不能保证的结果。只概括正文确实包含的内容，不写成空泛宣传或额外承诺；默认放在交付消息中，不自动并入 PDF、平台正文或封面。内部作品清单记录这段简介的当前文件，便于后续复用。

## 执行顺序

1. **读取与保存原文。** 用已知内容归档能力读取指定来源及原图，直接落到作品所属目录。按上节追到实际教程并记录章节覆盖、完整标题、正文、链接、图片顺序和缺失项。读取器提示未解析内容时检查原始结构，确认是分隔线、媒体还是遗漏正文，不能把部分读取报成完整。
2. **读取飞书现状。** 用户指定已有飞书文档时先读取正文、图片块 ID 和相邻段落。已有内容与本轮目标对比，避免重复追加；只补必需部分，不新建副本替代原文档。
3. **选定人物与视觉。** 人物出现次数与面积按[当前人物密度要求](visuals.md#人物密度按当前要求)执行；实际使用前查看[已选 AiGoodBro 形象](aigoodbro-character.md)：无眼镜、Bro 蓝夹克、宽松直筒裤。品牌形象使用全身人物或半身头像，可配已确认字标，不硬插、不遮挡信息，不沿用旧软件图标。先判断已有操作截图是否足够直观，再按[截图选用规则](visuals.md#已有教程截图先判断是否直观)决定包装方式。沿用当前作品已确认的配色和 GBro 红蓝白视觉约定，字体按[已确认样稿](visuals.md#字体沿用已确认样稿)固定；文章封面和内图使用合适的阅读画幅，小红书版本按 3:4 制作。
4. **逐图设计与制作。** 给每张图记录对应段落、教学目的、保留的事实、拟用文案及原位置。区分人物插画、概念流程图、真实截图和结果整理图；保存实际提示词，调用当前图像工具生成可用成品。截图按[精确品牌包装](visuals.md#教程截图的品牌包装)处理，保留数据、选项、模型名和数值；整理成示意卡时清楚表达其性质，不伪造功能界面或结果。
5. **看图验收。** 对照上下文检查文字、数值、箭头方向、流程分支、人物身份、Bro 拼写、无眼镜、宽松裤型和手部。发现错误只修受影响的图；未通过版本不能作为上传成品。
6. **按指定形式交付。** 只要本地资料时完成本地文件；用户说“发飞书／发送到飞书”时按[机器人交付流程](delivery.md#每篇每个平台独立成组)发送本次指定版本。用户明确要求更新飞书文档时，空文档按原段落与图序写入；已有完整正文时优先原位替换对应图片块，保护正文、链接、其他资源与评论。每轮结构修改后重新读取，再继续依赖块 ID 的操作；发生部分失败时核对现状，仅补未成功部分。新建云文档不能代替机器人发送素材。
7. **核验与归档。** 核对图片数量、顺序、实际资源和正文；保留正文的任务要比对文字与链接一致，远程交付另须回读。按[储存规范](storage.md)维护唯一成品、来源、角色引用、提示词、修改记录及实际交付入口。教程、包装配图和商品素材可分别沿用不同版本，清单写清配套关系，不因修改文案而复制图片或虚增版本。整理与缓存归位按用户要求直接移动，不另建镜像副本；图像历史版本保留明确用途与状态。最后交付实际完成的文件、远程入口和未完成项。

## 按需协作

当前任务已要求多账号协作或已有对应调度约定时，新的生图任务沿用用户的 **5xPro** 账号优先偏好；审图、素材整理、布局或分段检查等独立工作按实际分工处理。只拆有独立交付价值、收益大于交接成本的部分，明确负责的文件或图段，统一来源、品牌素材、输出位置和验收标准，由主任务整合复核。已经完成并验收的图片不因账号偏好重做，也不为消耗额度新增素材。

实际调度先读现用 多账号管理（外部可选依赖，见[分发说明](distribution.md)），按其入口核对账号身份、参与状态、新鲜额度、占用和目标环境的真实工具能力。5xPro 是账号套餐偏好，不是模型名，也不证明该 CLI 能调用本次桌面生图工具；具体账号随当前状态选择，不把字母、profile ID、暂时额度或套餐识别值固化到内容 Skill。

用户对当前任务的执行授权覆盖范围内的必要分工；持续沿用已有授权，不因此切换中枢身份、改认证配置或启用额外付费。没有可用账号或目标工具时，说明受影响的步骤并继续其他已授权工作，不冒称已派发或把当前桌面生图用量归到 5xPro。只有真实派单及工具回执能证明执行账号和结果。

用户要求配合 Jev 时，按 Jev 使用规则（外部可选依赖，见[分发说明](distribution.md)）处理页面观察与操作决策，报告实际执行范围；参与一次导航不代表审核过整篇教程。没有相应协作要求时，不为套用案例额外调度账号或操作页面。

## 完成边界

完成本次要求的正文、实际图片或 Word 并通过相应验收，才能报告对应本地成果完成；要求飞书发送或文档更新时，还须完成对应动作与回读。只生成提示词不能报图片完成，本地验收也不能报远程交付完成。本触发词不自动授权公开发布 X、微博、小红书或商品上架，也不为其他文档或平台扩大已有授权。
