# 发布续接与时间首句

## 先找已指定的对话

每次开始或继续发布，先读取用户指定的发布来源对话和本篇最新回执，再选择入口。优先使用本机 `~/.local/share/gbro-publish/config/publishing-continuity.local.json`：其中的 `thread_id` 定位指定对话，`work_root`、`manifest` 和 `receipts` 定位已保存的成果与运行记录。配置只存本机，发布包只带空值示例，不公开聊天内容、私人路径、接收方或账号配置。

支持读取对话的宿主按 `thread_id` 读取有关发布的最近结果，必要时再读更早的关键步骤；不要重读整段聊天。没有跨对话读取工具时，读取本机配置指向的作品清单与回执，明确使用文件续接；缺少来源指针时才定位用户指定记录，不猜另一条同名对话。

历史记录用于复用已证实的入口、字段映射和修复，不直接重跑带旧素材、旧账号或最终提交动作的脚本。原对话的部分成功不是全平台成功；新稿仍核本次版本、目标身份和重复内容。同一任务既有授权持续，必要修复和工具失败不增加口头确认；只修改 Skill 不启动历史稿件发布或监控。

## 最小执行顺序

1. 从本篇清单读取已验收的视频、封面、文案和最新回执。按平台分别记清：尚未上传、已上传、已存草稿、已排期、已提交审核、已公开、修改待确认或受阻；不从旧文案 JSON 的缓存状态推定结果。
2. 优先复用同账号已成功的工具与参数映射。入口、环境、媒体要求未变时，复用本次有效核验；只复查发生变化或尚缺证据的条件。浏览器标签 ID 属临时状态，重新发现当前标签，不长期保存为发布入口。
3. 上传前集中核对账号、正文、封面能力、AI 声明和文件权限。素材含合成人物或其他实际 AI 生成内容时，复用旧素材也要按平台要求声明；分别记录声明是否保存成功。
4. 本地文件上传明确要求扩展开启 `Allow access to file URLs` 时，记录需要用户操作的准确入口。条件没有恢复证据就不重复等待同一个上传，也不换协议、工具、外部托管或修改全局安全配置绕过明确拒绝。普通会话失效与安全拒绝分开处理，修复后只续该平台。
5. 修改已发内容时按确切作品 ID 原位编辑并回读；不以删帖重发代替编辑。无法修改的视频或超过编辑限制的帖子保留原状态，报告具体未改项。用户已自行发表的稿件不重复提交。
6. 提交结果不明，先查后台或公开页。成功回执须包含账号、作品 ID／URL、时间、文案版本及封面／声明状态；上传、排期或退出码不等于公开发布。失败只暂停有关动作，继续独立工作。

共享浏览器窗口由一个执行者操作；文件修改、文案整理与独立接口读取可以并行。主代理负责汇总各平台回执，避免多个代理对同一作品重复提交。

## 重置消息必须先说时间

正文第一句话直接写本次重置的日期、具体时间和时区，再写行动提示、解释与话题。新制作的视频开场字幕／口播同样先说时间；英文段保持相同时间、时区和确定性。标题与封面能容纳时也时间优先，不能为了字数删掉决定事实含义的“预计／之前／陆续”等词。

已知时间的结构：`[日期][时区][具体时间及之前/左右等限定]，[产品与重置安排]。` 未公布具体时间时第一句明确写“重置时间尚未公布”，不编日期或沿用上一条的时间。阶段、范围与到账状态按本篇材料区分，用户提供的时间不冒称已获官方独立核实。

沿用已确认的图文、封面、视频风格和本次获准的平台及交付流程。更换日期时同时检查中英文文案、画面和文件版本，发布前再次检查已跨过的时间边界；不把过期的“将于”作为当前预告补发。
