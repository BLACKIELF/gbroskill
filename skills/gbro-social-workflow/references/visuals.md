# 图文质感、品牌与真实截图

各平台封面比例、制作尺寸、上传预算和当前限制按[平台规格与话题](platform-specs.md)核对；AiGoodBro 品牌预设已确认的小红书视频封面 4:3、1600×1200 保留。
做图、换封面或更新图组时读取；公开素材遵守[渠道边界](delivery.md#各渠道的链接与行动引导)。普通社交图文以真实分享的质感为默认，AiGoodBro 红蓝白用于克制的品牌提示。现有已确认样稿和用户当前改法优先于专项技能默认的紫绿、薰衣草、真人出镜或额外风格问卷。

## 真实截图是图文交付条件

GBro 制作的每篇图文成品至少附一张能核对正文核心事实或操作入口的真实屏幕截图；涉及不同界面的关键步骤分别配对应截图。X 原帖截图按下述[原生界面规范化](#x-来源帖子的原生界面规范化)处理。截图可以来自已授权的原帖、既有实操记录或当前实际界面，资讯与观点稿可用所讨论的原始资料画面，原件保存并记录出处、取得时间和对应段落。概念图、卡通图、AI 重绘界面、单独译制图及文字卡片不能充当真实截图。

软件介绍以真实软件界面为主要配图材料。介绍多款软件或多个关键界面时分别配图，数量按覆盖范围和可读性决定，不能用一款的截图代表整套产品，也不以文字卡代替软件画面。

先目视确认截图里实际出现的产品、状态、按钮和结果，再在本篇设计语言中包装。保留可辨认的原始屏幕画面，不用生成工具重绘截图本体；中文解释通常放外围，用户明确要求界面中文化时按下文局部译制。公开图组只交包装成品，原件留本地供核验。若截图显示账号、凭证或其他私密内容，先选安全的真实画面；不能安全处理时停用该图。

取得不到相关真实截图时，继续完成可独立交付的文字草稿并记录缺口，不用示意图顶替，也不把该篇报为图文定版或已完成配图。用户明确只要文字、只讨论或只改局部文字时按本轮范围交付，但不以“文章”二字推定免除已要求的图文截图。

## 视频封面与实帧

AiGoodBro 品牌预设后续小红书视频封面统一沿用已确认样稿（原私人参考未随包提供；请使用自己已授权的素材）的规格，默认直接制作，不重复询问比例。制作时复用可编辑排版（原私人参考未随包提供；请使用自己已授权的素材）的字体层级、间距和图文关系，在新作品目录产出，不覆盖样稿。

- 画布固定为横向 4:3，常规导出 1600×1200、不透明 PNG；不套用图文组图的 3:4，也不因原视频为 16:9 而改变封面画幅。
- 白底，红蓝黑文字。顶部左对齐安排短引题、粗体主标题和一行补充说明；红色强调核心数字或关键词，蓝色引题需要强调时用细直下划线。左右边距沿用样稿约120px，字号随实际标题长度调整，手机缩略图须可读。
- 中下部按视频内容排实帧。多种动效、艺术风格或场景展示优先用多张清晰、彼此不同的原视频截图，例如3列×2行等大拼图；先实际看候选帧，选主体完整、视觉鲜明的画面，避开模糊过渡、重复效果与无关编辑器画面。叙事或单一主体可沿用左大右侧两小布局。配简短类别或主题名，保持原比例、完整主体和内容所需字幕，不用生成插图顶替。
- 底部左侧放与本篇交付对应的简短说明，右侧放已确认的 AiGoodBro 字标和小头像，均完整露出。没有对应说明时按删除后重排规则收紧，不保留空标签。
- 只复用版式规格，不沿用样稿的主题、数量、青蛙／太阳／皮影素材或模型效果结论；“喂饭级教程”等字样仍须满足正文提供可复制内容的条件。
- 导出后实查1600×1200尺寸、完整封面及400×300手机缩略图，核对文字层级、主体、字幕、标签和底部署名，没有遮挡或裁断才交付。

上述默认仅适用于AiGoodBro 品牌预设的小红书视频封面；图文组图及其他平台按各自规格。用户当轮明确另定尺寸或版式时按新要求；出现与已确认规格冲突的实际裁切框时说明具体差异，再处理受影响画幅，不静默改成其他比例。

演示类视频的封面素材从对应原视频截取，先看关键帧再选；用户框选类别、指定画面或提供截图时优先匹配这些画面，不能自行换成另一组。未指定时选主体完整、动作清楚、画面有辨识度的真实帧。原视频自带的字幕与知识标注可以保留，不为追求干净刻意去字；只裁无关播放器、外框与账号信息，保留内容所需的证据。

保存完整帧、截取时间和裁切范围，直接等比嵌入原始画面，不用生成插画、近似重绘或“风格示意”顶替视频截图。X 帖子的局部规范化不能改变视频演示画面。用户明确要求实帧原貌时，复用既有排版能力组合原像素，需要生成的外围素材另按 imagegen 流程处理。

## X 来源帖子的原生界面规范化

AiGoodBro 品牌预设给到 X 推文或截图用于图文创作时，尤其是 Tibo 的内容，默认以真实原帖界面为主体做局部规范化。保留原生帖子、评论、投票的结构、字体层级、阅读关系和配色，用简洁边框把帖子整体框起，留适量内边距；边框框住完整证据区域，不只圈头像。不另画一套仿 X 卡片，也不把推文替换成大字海报或摘要卡。用户的样式参考只影响外围画幅与包装，不覆盖原帖身份、内容和数据；明确只要文字、原图或限定局部时按当前范围执行。

- 先读取原帖、必要引用及相关回复，实际查看真实截图并保存完整原件；用户指定浏览器或读取方式时沿用。核对 Tibo 等作者与实际来源，不凭昵称匹配另一个账号。二手文章、搜索摘要和文本接口不能代替原生截图，拿不到实图就记录缺项，不用假界面补齐。
- 按[评论区取材](content.md#原帖评论区取材)挑出的有趣评论或重要补充，可以和主帖同页展示，或在确有必要时另做一张评论图。使用真实评论截图，保留原生回复层级、评论者头像与必要显示名，头像沿用默认不隐藏规则；主题帖与精选评论的边界清楚，多条不相邻的回复分开展示，不拼成连续对话。外围短注讲清看点，译文与自写点评不嵌成原作者发言；同样清理平台标识和域名，保持主帖优先与手机端可读性。
- 原帖或评论附带的贴题图片、截图、投票图和视频封面，按需与对应文字一起查看和取材；优先保留原图的主体、文字和证据关系，可和原生帖子或精选评论同页呈现。图片属于评论时明确归属，不把评论配图排成主帖内容；图片本体的实质内容、人物和数据不重绘、不改写。X 平台标识、x.com、无关导航等仍按本节规则清理，无法安全处理时留作内部证据并报告缺项。
- 默认不隐藏原作者头像，保留真实头像、必要显示名及理解帖子关系所需的原生元素；只有用户明确要求删除时才去掉头像。Tibo 的头像不能按一般去署名规则删除，也不用 AiGoodBro 头像替换。保留正文、引用／回复关系、时间、投票条、百分比、票数和互动数字；普通回复、转发、点赞等原生图标可保留。公开稿继续不写“@账号”或账号 handle，移除时只收紧对应区域，不删掉整个头像作者栏。数据来自同一份原图或采集记录，不虚构评论、点赞或操作状态。
- 移除 X/Twitter 平台标志、作为平台标识的 X 字样、x.com／twitter.com 域名、来源跳转入口和链接预览；无关导航、地址栏、手机状态栏及外层页面一并裁去。沿用现行规则移除无关的 Grok 入口、浮动按钮与图标；产品名或术语本身是正文内容时保留，不逐字符删掉 Codex 等名称里的字母 x。小红书、公众号图片中的其他可见网址与二维码按[渠道规则](delivery.md#各渠道的链接与行动引导)处理。这是AiGoodBro 品牌预设的素材要求，不据此保证平台审核或认定限流原因。
- 中文解释优先放在帖子外；明确要求中文化时只局部译制，保留原意并标明译制，不写成作者原本用中文发言。新增观点、重置阶段判断和预告标题放在外围或正文，不排成作者原话；投票和回复里的意向不能在画面里改成官方结论。
- 关键词默认按[直下划线规则](#关键词只用直下划线)强调；当轮明确要红圈或红线时只改指定处。修补移除区域的背景、间距与对齐，保留其余原生界面；原始截图留本地，公开交局部处理后的成品，内部记录处理范围，不称未经编辑的原图。

涉及图片编辑时沿用当前 `imagegen` 编辑机制和工具约束，仅处理指定区域；对照原件逐项核对头像、原话、数字及界面结构，不允许编辑结果改脸、改字或整张重绘。实际查看最终全图与手机缩略图，确认帖子整体边框、原头像与必要显示名完整，X 标志和域名清除，正文及数据可读、无残字和大片空白；局部失真则修复或保留缺项，不报完成。没有新差异不重复处理。

## 删除后的重排

用户要求删除署名、账号、标签、图片或一段文字时，完成标准包括删除内容和修好删除后的版面。先判断哪些头部、分隔线、边框、占位与说明随被删内容失去作用，一并移除或收紧；不要留下空的作者栏、悬空标签或明显过大的无意义留白。

按剩余内容重新安排对齐、字号、行距、内边距、卡片高度及相邻模块位置，在最小必要范围内移动或调整尺寸。删除元素不等于锁死其旧位置；保留主题、正确文案、图像身份与既定品牌，合理利用释放的空间，不用新文案、装饰或假数据填空。制作、重排等过程说明留在内部，公开成品不默认展示；确有理解作用的说明与用户明确要求的标签才保留。

同步检查受影响的正文、图片及维护稿，已确认的模型建议或使用条件保持一致。验收必须实际查看最终全图和手机缩略图，确认空白合理、文字可读、对齐协调、相邻卡片衔接自然，底部字标与头像完整；仅确认被删内容消失不能算完成。

## 关键词只用直下划线

AiGoodBro 品牌预设新加的关键词强调只用细、水平、粗细一致的直下划线，线放在字下方并与文字留间隔，长度贴合所强调词句。颜色沿用当前样稿的少量红或蓝，不盖字、不碰统计数字或下一行；只标核心词句，不给每行都加线。

删除作为重点标注的手绘圈圈、圈线、回钩、弯曲划线和放射短线，恢复原背景后用直下划线替换；不另加涂抹、荧光块或装饰箭头。原生圆形头像、表情、认证标、投票选中符号和内容必需的流程箭头保持，不能把这些当作圈注删掉。除非用户当轮另有明确要求，不恢复手写风标注。

## 先安排每张图做什么

先按[本篇切口与体裁](content.md#先锁住切口与体裁)决定每张图的作用，再定页数。没有明确页数时，单一趣味互动通常 1–3 张足够，复杂教程或干货合集可用约 6–9 张；这些是容量参考，不是最低张数。不为凑页数拆空页，也不因历史稿有六张就沿用六张。已完成的单页修订不触发整套重做。

AiGoodBro 品牌预设的小红书单条交付按最多9张图安排，封面计入总数；需要9张教程时采用1张封面＋8张主要步骤。备选封面单独交付，不把两版封面都算进同一组待发图片。长教程可以提取主要操作、关键前提、完整可用指令与对应截图进入9图，完整正文另存配套PDF；配文写清“主要步骤”，不能把精华版说成全文，也不交数十张全文分页图让用户自行压缩。收到其他明确张数或分篇要求时按当前范围执行，这是一项用户交付约定，不把它冒称已经实时核验的平台上限。

趣味互动可用“封面原话／反差 → 真实互动与最短上下文 → 可选点评或接梗”。一张能讲清就一张；封面与截图同页也可以。截图里保留理解谁在说话、回复关系所需的内容，点评放外围，不把本稿接梗排进伪造的原帖画面。品牌和小幅人物给主体让位。

介绍替代、兼容或独立重写的软件时，封面直接写出它对应的原软件名称；多款可用准确的配对总览，后续内页逐款展示真实界面。

封面只突出一个主钩子，再用一处真实画面或少量具体用途补充；正文第一段承担解释，不在封面堆完整背景。教程内页按读者任务展开，每页讲清一个动作、前提或结果。看到高赞参考使用纯文字卡，也不能据此省略本篇已要求的真实截图；参考帖的角色和配色不覆盖 AiGoodBro 品牌约定。

用户点名进度条或时间轴时，必须实际画出对应图形，标明起点、终点和当前状态，不能仅列几行时间替代。时间差统一时区并从原始时间计算，注明是帖子发布间隔、实际运行耗时还是账号到账时间；没有证据不画运行百分比或宣称全部账号已到账。

“内容尽量写进图片”指把本篇关键内容放清楚，不以满版为目标。趣味稿保留原话、语气和互动，教程才按步骤承载细节。调用 `xhs-html` 等排版能力时沿用本篇页数；使用工具已有的页数参数完成布局检查，不为通过默认六页或“三类干货”的检查而补无关内容，不修改共享校验器来掩盖溢出等真实问题。

可参考两种结构：

- 工具清单：封面 → 按用途/免费方式选工具 → 分组卡片 → 关键风险 → 选择与领取注意。
- 有实机证据的清单：封面 → 关键截图解释 → 分版本/分平台卡片 → 风险 → 选择建议。截图新增后同步页码与文中指向，不遗漏清单后半段。

“吸引关注”的工具介绍默认一张信息完整的产品卡：真实标识或产品名 → 最强数字/收益标题 → 具体用途与演示 → 少量关键词或已核实福利。按用户选定的参考图安排层级，不自动扩成多张教程。

卡片保持平台、免费权益、模型、期限一一对应；内页文字承担细节。封面承诺的数量必须全列完。截图页已有的信息，后面的总览可压缩成便于比较的一行，不无意义重复。

## 日常分享的质感

普通资讯、趣味互动和实操笔记，要让读者先看到发生的事、界面和作者关注的具体细节。设计帮助看清材料；默认降低宣传册、招商页式的商业感。明确制作订阅广告、商品介绍或指定宣传页时，仍按该任务目的处理，不用这条删掉已要求的销售信息。

先按材料选择呈现方式：实操记录展示问题、来回确认与结果；界面批注指出入口、动作和容易卡住的地方；观点短卡用一句具体判断带出正文。大字封面、清楚的表格和精细图解都可以使用，不把“活人感”简化成手机拍屏、粗糙排版或统一截图模板。观点封面可以文字主导，整组仍须满足本篇已要求的真实截图。

新闻或产品更新类可沿用用户选定的证据卡样稿（原私人参考未随包提供；请使用自己已授权的素材）：白底，顶部左侧小栏目、右侧本篇已核实日期；黑蓝主标题突出产品名与核心变化，按长度断行；浅蓝短标签说明有证据的阶段或状态。中部以原帖与跟进回复等证据界面为主体，只给关键句加短直下划线，底部浅蓝窄条放一句简短总结；一张讲清就不拆组图。沿用 GBro 红蓝白及现用 AiGoodBro 字标、小头像，标题和署名在手机缩略图中完整可辨，让证据界面占主要空间。X 来源按上方原生界面规范化保留原作者头像和必要显示名，清理平台域名与 Logo；AiGoodBro 品牌放外围，不替代原作者。真实软件截图仍不能生图重绘。此布局限于适合的图文资讯，不扩展到视频封面、教程步骤或商品页。

- 有过程或操作证据时，让相关截图或实际结果承担主要说明，外围用短评、局部放大或直下划线指出重点。保留读懂任务与回复关系的最小上下文；不把完整现场压成一小条截图，再用大段包装文字重复解释。教程标注应能回答“看哪里、做什么、怎么知道做对了”，不只加装饰箭头。
- 一页只强调一个重点，减少多层大字标题、满页红蓝粗体、口号、重复总结和无必要的圆角卡片。标题要吸引人，画面仍可克制；“标题党”不要求每页都长成广告封面。
- 同组按材料改变构图：整张截图、局部证据、短说明可自然切换。只做理解所需的页数，一句有趣的回复不拆成连续几页分析；不强行保持每页相同的品牌页眉、大标题、边框和人物位置。
- AiGoodBro 署名按[当前人物素材](aigoodbro-character.md)使用小幅半身头像、全身人物或已确认字标，不使用已停用的旧软件图标，红蓝色只点关键处。讲解、接梗用的人物缩小且不反复摆同一姿势；明确要求逐页角色的教程仍按当轮要求轻量放置。
- 图中评论像人在指出某个具体细节，内容和语气跟着材料走。自然感来自真实素材、实际观察和取舍：确有疑问、修改或不完美结果时保留关键部分，不一律剪成成功宣传。不能补造亲历、对话、翻车或劳动量。新增强调按[直下划线规则](#关键词只用直下划线)执行；不为自然感故意做错字、歪斜或模糊。

验收先看缩略图第一眼注意到什么：事件、具体观点或操作问题应先于品牌包装。再逐页看是否只是在重复标题、解释已经懂的笑点，或添加没有阅读作用的装饰；删掉这些重复，再检查美观与一致性。排版清楚和有个人表达可以同时成立，不能凭设计精细或字号大就判为商业化。

## 视觉约定

制作 AiGoodBro 封面、讲解插图或步骤引导中的人物时，读取本包[人物与字标参考](aigoodbro-character.md)并实际查看真实素材；缺失时报告，不按文字臆造同一人物。当前选定无眼镜、Bro 蓝夹克、宽松直筒裤的角色；同一份素材可取小人头、半身头像或全身照，封面与内页的出镜密度按下文处理，不退回旧软件图标。角色设定图本身的 3:2 比例不覆盖平台画幅；文章封面和插图按当前平台及阅读布局处理。

- 小红书图文组图的真实尺寸必须为 3:4，背景不透明；常用 1080×1440。工具输出其他精确 3:4 尺寸可沿用，不声称是没有导出的分辨率。视频封面按[已确认的裁切画幅](#视频封面与实帧)处理；其他文章封面、正文插图按当前平台与阅读布局处理，不套用图文组图画幅。
- AiGoodBro 品牌预设后续小红书图文封面沿用已确认的缩略图规格（原私人参考未随包提供；请使用自己已授权的素材）。只复用画幅、字体层级和标题／底部署名的可见位置，不继承样稿主题、正文或数字。全图与手机缩略图都要目视核对，主标题、AiGoodBro 字标及卡通小人头同时完整可辨、不被裁切；小头像仍不抢主体。生成工具的精确 3:4 尺寸可等比沿用，不能凭口头说明声称已适配。
- 默认白底、浅灰底或适量留白；红蓝用于少量重点、直下划线或署名，不要求每页红蓝交替强调。不要使用 Jev 账单封面所示的深海军蓝（约 `#02225C`）作大面积背景或渐变主色；此前选过深色卡片也不自动沿用这种底色。保留原始软件界面的真实颜色。
- 封面主标题未定时可压到 8–10 个汉字附近，型号或必要英文可另排；用户已经选定完整句子时逐字保留，可用断行解决长度。字号以缩略图能读清为准，真实画面本身有吸引力时降低文字占比，不统一用占据半页的巨字，不堆整张清单。
- 默认不加真人；有真实产品/界面素材就用它突出具体结果。不要凭空生出设备、功能或官方认证。
- 新发布模型或产品已有用户提供的真实界面时，默认将原截图等比嵌入封面作为主证据，生图只处理外围，不重绘型号、选中状态或控件；原件留本地核验，发送按交付参考。只有用户明确指定不用，或说“你判断”将素材取舍交给我时，才自行决定是否放封面。
- Logo 从官网、官方仓库或已核实素材取得，保留原形与品牌色；不能让生图模型凭印象画一个。项目没有标识时用产品名，不把底层模型的 Logo 冒充项目自己的 Logo。
- 内页标题明显小于封面；数字和条件突出，细节保持正常阅读大小。太挤先拆内容，不把字缩成脚注。
- 边距按已确认样稿及缩略图可见范围安排，保证主标题和底部署名完整；没有基准时可留约 8%–10% 安全边距。整组字体与基本色系统一，需要导航时加页码；对比页、截图页、清单页各按内容布局，不用重复装饰维持统一。
- 用户满意旧稿时，先确认旧稿真正有效的结构和视觉锚点，再做局部增强，不用全新模板替换已接受样式。

用户点名认可刚做的 Muse AI 盒子等现有排版时，先定位对应成图、源文件和最后确认版，再借用它的信息层级、留白与图文关系；产品同名或生成时间最新不能代替用户选定的样稿。历史 Oracle、Next 样本只在相关时读[已确认案例](confirmed-example.md)，当前要求与本页视觉约定优先。

### 字体沿用已确认样稿

用户说“之前的字体好”“字体不稳定”时，先找到并实际查看所指成图和可用源文件，记录本组的字体来源、字重、标题与正文层级、行距、断行和对齐，再改受影响的文字。历史宽厚粗字封面（原私人参考未随包提供；请使用自己已授权的素材）可作为曾回看的字形参考，不把它的满版大字、题材数字、旧权益或品牌元素一并固定成所有新稿的模板。

- 生图时把实际样稿作为风格参考传入，明确沿用字形、字重和层级；不要只写“粗体”“高级感”后逐张重新设计。遵守当前图像工具规则，纯生图只能验证视觉接近，不能声称使用了某个精确字体文件或像素级一致。
- 用户已选择可编辑排版或 PDF/Word 流程时，复用源文件中已确认的字体与样式，检查字体可用性和导出结果；不能把生图文字、系统回退字体和另一套文档标题样式随意混成一组。缺少原字体时说明替代范围，不冒称原样复现。
- 已确认样式直接复用，不例行增加审批。用户明确要看字体样张或要求新风格时，先交一张实际样图；其余内容按当前阶段授权继续。仅“还可以”不等于整套定稿，有歧义的反馈不擅自改写成另一条视觉偏好；助手自行做的修订也不自动成为用户确认版。
- 验收并排看样稿与新图的全图和手机缩略图，核对字形、粗细、层级、行距、边距和中英文混排；OCR 正确不代表字体一致。字体复用与留白、轻品牌同时成立，不因保持粗字就把每页做成密集广告封面。

### 人物密度按当前要求

AiGoodBro 品牌预设的 GBro 封面（含直播封面）默认带一个已确认角色的卡通小人头，放在角落或底部署名旁不醒目的位置，作为轻量身份标识。只露头像或少量衣领，不默认放大成半身或全身主角；尺寸以缩略图里不抢标题和主题素材为准，不遮挡内容、不贴边裁切，不用高亮边框或大色块把头像再次变成视觉中心。使用已有角色原图作身份参考，不能凭文字另造一张脸；明确不要人物时按当轮要求去掉。

这项封面约定不扩展为每张内页必须出镜。内页按讲解需要选择小人头、半身头像或全身人物；“卡通形象减少”同时减少出镜页数和所占面积，截图、表格及对比证据页可以不放人物。文字署名可保留已确认字标，不用旧软件图标补位。角色放在外围，不遮住关键界面或冒充官方账号。人物出现时核对无眼镜；衣服、裤装或手部可见时，再检查 Bro 拼写、宽松裤型以及手指、手腕和抓握结构。

## 局部改图

“删除”配局部截图时，先定位当前完整版里的对应文字，删除指定内容并补齐原背景，保留其他正确文案、Logo、配色和数字；按[删除后的重排](#删除后的重排)调整受影响的间距、卡片及相邻布局。不得另加近义前缀，或借机重写整张图。标题与图中文字按内容参考直接表达，“作者原文称”“作者对比演示”不作为固定装饰标签。

编辑后与上一版对照目标区域及其他文字，防止删一处却改错别处。工具失败或额度不足时保留旧版，准确说明新图尚未完成，不把旧图当作修改后成果交付。

标题、断行、标点、画幅和逐词颜色按本轮要求锁定。用户只改文案或把正文提为标题时，沿用本篇上一已确认版的字体、颜色、渐变和样式；只重排受影响区域，不自行换配色。只改封面不等于可以改内页；保留原图的相对顺序，新增细节图可以插在对应段落之间。用户说“先给封面”就先交实际封面，完整提示词保留实际发送版本。改色后逐词核对颜色，不能只凭 OCR 正确就通过。

## 原图与包装图

先查看用户原图，保存完整原件；用户给作图文素材的截图，每张都按当前作品的设计语言制作包装版，未包装原件不作为交付成品。输入图按真实证据、主体或风格参考区分，不混用。

包装可以增加白边、背景、标题、直下划线和注释；重点标注按上文规则处理，不新增圈线。尤其保留：完整免费模型名、Free now / 限时免费 / 夜间免费等标签、0×/0.00x 倍率、划线原价、活动日期和时段、与结论有关的详情弹窗。

裁图仅裁无关外围，不裁掉上述证据；原图偏横时先把完整关键区域等比放入本轮确认的画布，再安排标题说明；图文组图与视频封面的比例分别按上文处理。下划线和注释不能遮字；原图用于强调的手绘圈线、曲线先按上文规则删除或替换，内容必需的原生图标和流程箭头保留。为了适配公开链接规则，可以去掉无关地址栏；若关键证据和敏感信息无法安全分开，改用其他已核实画面或清晰标为信息摘要，原图保留在内部。

所有图像编辑遵循当前 `imagegen` 工具要求；本地目标先 `view_image`，全部目标都有路径就用路径引用，否则用覆盖目标的最少近期图片数，两者不混用。不要靠编程重画伪造软件菜单；用户明确选择精确 HTML 排版时按该范围执行。

生成后逐项对照原图检查型号、数值、标签、删改与遮挡。模型写错原图关键文字时继续修复；证据不可还原就不将该包装图作为可信实机图交付。包装图的交付按[分组规格](delivery.md#每篇每个平台独立成组)，原件留本地核验。

### 已有教程截图，先判断是否直观

先看对应操作步骤与真实截图，检查读者能否直接认出入口、选项和结果，再决定怎样做“新包装＋实图”。仓库文本提取没有图片时，可检查 README 原页、已有演示和相关实操视频；没有产品界面的 Skill 可用真实仓库文件或调用结果截图，不虚构仪表盘。

清晰且相关的截图优先保留，外围补标题、中文解释、步骤或验收点；局部可用的只裁无关顶栏和外框，必要时增加真实局部放大。截图太小、过时或去掉无关内容后失去教学价值时，换已核实实图；示意图可作补充，但不计入真实截图要求。素材来源、帧时间、译制和取舍记录留内部。

### 教程截图的品牌包装

按[教程范围](tutorial-rework.md)处理已授权的正文、署名和图片；不把作者经历改成用户经历。软件核心区域保持完整和比例，标题、品牌、人物与装饰放在外围。用户点名替换署名或站点角标时只处理指定区域，检查完整旧字串及边角残字，不用小白块粗糙盖住一部分。

教程需要英文界面的中文译制时，先沿用已知的中文支持情况；尚不清楚且决定呈现方式时，只问软件是否支持中文。确认支持中文且用户要界面中文化时，可只替换标签和说明文字，做到字体、间距、背景自然一致；不支持或尚未确认时把中文说明紧邻英文。产品名、模型名、token、数值、选项顺序和操作状态保持真实，内部记录译制区域与原图；译制图不声称为原生中文截图。翻车对比、原始对话等证据保留原文，翻译放在图外。只要原图时按原件交付。

用户明确要求把某个邀请码等输入字段替换进教程截图时，只对可编辑字段做定点修改，原图单独保存；新值须在衍生图、配文及正文中完全一致，逐张目视排除旧值残留和编辑痕迹。不能顺势伪造成功支付、账户权益或软件原生功能，内部标记该图是修改版，不将其计作未经编辑的原始截图。

截图语言与正文语言独立；英文截图不授权改中文正文或发布英文稿。需要展开某个控件时必须实际看见相应选项，开发或隔离演示画面分别标清。Word/PDF 中再核整图比例、二次裁切和浮动遮挡；原件模糊就说明，不推测补画。

## 验收与交付

- 逐张看全图与缩略图；检测实际比例、页数、字符、溢出及页码。OCR 只辅助发现错字，不能替代对照原图。
- 校对标题、正文、表格、截图解释、封面数字一致；重点复核免费/优惠、版本、期限，按渠道规则删除小红书、公众号成稿中的网址，核对相应行动引导。
- 用户要“图片做好/完整版”，交付实际 PNG/JPEG，而非只有提示词或 HTML。HTML 可作可复制正文和全图预览入口；离线自包含，桌面和手机可阅读，图片放大与下载按交付承诺核验。
- 已确认封面继续复用时明确复用；只改受影响的页，更新清单和页序。源文件、原图、候选和成品在已有项目内分开保存。
- 图片不在飞书维护表中重复插入。素材消息、维护文档是两种不同用途。
